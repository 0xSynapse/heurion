AEGIS OS · TUTORIAL · 2026

从安装到第一个
多 Agent 任务

这份教程面向第一次使用 Aegis OS 的开发者。完成后，你会有一个可隔离的 Agent 工作区、 一次经过批准的记忆访问、一个可撤销的 A2A 任务，以及一份可查看的审计记录。

预计时间：10–15 分钟。支持 macOS / Linux；不支持 Windows。

0. 准备 1. 安装 2. 接入 Agent 3. 记忆同意 4. 多 Agent / A2A 5. 撤销与审计 6. 升级、恢复与卸载 7. 故障排查

00 / PREPARE

准备

你需要：

  • macOS 或 Linux 终端
  • Homebrew（macOS / Linux 均可），或使用一行签名安装脚本
  • 一个 coding agent：Claude Code、OpenCode、Codex CLI、Hermes 或 AGY
  • 一个 Markdown / Obsidian 笔记库（可选，用于记忆同意）

Aegis OS 目前不支持 Windows。不要把真实生产密钥放进示例目录；教程使用本地临时项目。

01 / INSTALL

安装 Aegis OS

# 添加 Heurion tap 并安装
brew tap heurion-org/aegis-os https://github.com/heurion-org/aegis-os.git
brew trust heurion-org/aegis-os
brew install aegis-os

# 接入 AGY / Claude Code / OpenCode / Codex / Hermes（运行一次；加 --enforce 可安装父进程内核强制包装器）
aegis-os install

# 验证与 5 秒本地安全体检
aegis-os --version
aegis-os doctor
aegis-os audit-me

Homebrew 安装二进制后，运行一次 aegis-os install，把 Aegis OS 接入 agy、claude、opencode、codex 与 hermes；随后 doctor 应全部通过。

如果不用 Homebrew：运行一行 Ed25519 签名安装脚本 curl -fsSL https://heurion.org/aegis-cloud/install.sh | sh，或从 GitHub Releases 下载对应平台二进制，或从源码 cargo install --path crates/aos-cli。使用二进制/源码手动安装后同样运行一次 aegis-os install。

02 / FIRST RUN

接入 Agent

进入一个项目目录，按协作场景选择 Advisory 插件模式或 Enforced 父进程内核沙箱模式启动：

# 方式 A（Advisory 生产力护栏）：直接启动常用 Agent
claude
opencode
codex
agy

# 方式 B（Enforced 内核强制边界）：由 aegis-os run 作为父进程在 bwrap / Seatbelt 内启动
aegis-os run -- claude
aegis-os run -- opencode

Aegis OS 的 hook 会自动附加运行时。默认直接进入免费的 Local CoW 沙箱模式，你也可随时切换到 Cloud 模式：

模式说明与入口
Local免费本地模式（默认）：本机 CoW 影子工作区 + 内核沙箱，默认落盘于 ~/.aegis 按组织隔离的 OS 加密卷 OrgVault（macOS 无 root APFS Encrypted .sparsebundle / Linux LUKS2 + Btrfs 或 gocryptfs，AES-256-GCM 信封密钥 + fsync 原子刷盘），不脏宿主 Git 工作树且支持崩溃后无损恢复。
Cloud远程 64GB Linux LUKS2 + Btrfs 运行时（本地零 CPU/RAM 负载，空闲自动密码学级 Scale-to-Zero 休眠 umount + cryptsetup close，唤醒自动解锁）：支持免费体验档（aegis-os cloud up）与 Pro 专业版（$29/月，8 个并行 Agent）。前往 Aegis Cloud 控制台 (/aegis-cloud/dashboard) → 或运行 aegis-os cloud subscribe --plan pro --wait。

也可以在对话里直接说“切换到 Local 模式”或“切换到 Cloud 模式”。

验证隔离与边界审批

日常使用时无需手动输入 aegis-os 命令，直接在 Agent 对话中发出指令即可：

# 在 Claude / Codex / AGY 对话中输入：
修改 README 的标题，检查 diff 并提交回主目录

Agent 会先在 CoW 影子工作区内完成修改（fs_edit / workspace_diff），尚未写回宿主目录。当 Agent 调用 workspace_commit 合并回宿主机时，桌面环境会自动弹出 IDE 内置确认框或打开免密钥网页审批台（/approve 与 /aegis-cloud/dashboard，本地模式零配置直连、云端仅需输入订阅邮箱），点击批准后自动续跑，并在合并前通过跨进程提交锁与 verify_cmd 沙箱门禁确保主干始终可编译：

  • 网页内联彩色 Diff 预览（查看变更 Diff）：无需切回终端，直接在审批卡片内展开语法高亮的 Unified Diff（GET /v1/approvals/diff）与变更文件列表，所见即所审。
  • 防 TOCTOU 篡改的密码学哈希锁定（批准本次 · SHA-256 锁定）：单次批准会将租约严格锚定至审批时刻的规范化 Diff 摘要（sha256:<evidence_hash>，最长 15 分钟有效）。若 Agent 在你点击同意后偷偷修改哪怕 1 个字节，二次提交将立即因哈希失配被拦截。
  • 多敏感文件合并单卡审批与时间窗租约：一次提交若同时触碰多个构建/钩子敏感文件（如 Cargo.toml、package.json、Makefile），系统会自动合并为单张 workspace_commit_sensitive 审批单；同时也支持授予 15 分钟或 1 小时常规文本提交租约。

纯终端/SSH 下可运行 aegis-os approve（或简写 aos approve），在 Enforced 会话中也可通过 aegis-os diff --json 与 aegis-os commit --expected-diff-hash <sha256> 完成哈希锁定落盘。

03 / MEMORY CONSENT

记忆同意：只读批准的范围

UOMP 是 Aegis OS 执行的记忆同意协议。先给客户端写入 bridge profile，并导入笔记：

aegis-os memory setup claude --vault ~/Notes

这条命令会：

  • 导入 Markdown 笔记（默认 tag notes，可用 --tag 修改）
  • 在后台启动本地 memory server（默认 127.0.0.1:9374）
  • 写入 Claude Desktop / Cursor / OpenCode 的 MCP 配置
  • 不签发 Token，不授权任何访问

重启客户端，然后让 Agent 读取笔记：

# 在 Claude / Cursor / OpenCode 里
列出 notes/projects 下的笔记

第一次 tool call 会创建 consent request。Aegis OS 会自动打开本地同意页（127.0.0.1:9375）；在页面上勾选要授予的 tag / key，然后点 Allow selected。不需要另开终端。

# 如果浏览器没有自动打开，手动启动同意页
aegis-os memory ui

# 终端 fallback
aegis-os memory pending
aegis-os memory approve <request-id>

同意页会显示 request id、Agent、task id（如果有）、session id 和过期时间。批准后当前调用继续；拒绝则返回错误。

高敏数据不会因为 tag scope 被批量放开。同意页会把具体 key 单独列出，你必须逐 key 勾选；Agent 不能批准自己的请求。

验证

aegis-os memory sessions
aegis-os memory audit --limit 20

你应该看到 session 的 scope、过期时间，以及 allow / deny 审计事件。

04 / MULTI-AGENT

多 Agent / A2A

Aegis OS 用 Google A2A 作为 Agent 之间的协作总线。日常协作完全以 Agent 为入口（无需手动敲 CLI）——直接在主控 Agent（如 agy 或 claude）对话中下达多 Agent 协作指令：

# 在主控 Agent 对话中直接输入自然语言：
把 auth 模块的代码审查派发给另一个窗口的 claude-code，锁定我正在修改的路由文件，等它完成后合并

底层运行时会自动通过 MCP 完成全套事务级配合：

  • 通配符文件认领锁与自动释放（coord_claim）：Agent 动笔前自动声明锁定目标路径（支持 src/** 与 src/auth/*.rs 二维 NFA + 真实文件树重叠防撞，并对沙箱脚本越界写返回 coordination_warning 告警）；当 workspace_commit 成功落盘或任务结束时，文件锁会自动释放。
  • 层级化 A2A 子任务图与级联取消（ipc_request）：支持 parent_task_id 父子任务树与 depends_on 依赖编排；当父任务被取消时，内核自动递归取消所有未完成的子任务，并级联回收锁与租约。
  • 零轮询阻塞唤醒（ipc_wait）：既有生命周期 Hook 的实时信箱推送（_aegis_inbox），也为无 Hook 客户端（如 Codex CLI）提供原生 ipc_wait 阻塞等待同伴回复或任务状态变更。

任务级租约与可选终端看板

在网页审批台（/approve）批准绑定了任务的提交请求时，签发的租约会自动绑定到该 task_id（"kind": "task_scoped"），任务进入终态后租约立即自动撤销，同一 Agent 无法将任务 A 的租约挪用于任务 B。

如果你想在终端只读查看全局任务看板或手动管理租约，也可使用以下可选诊断命令：

# 可选：终端只读查看 A2A 任务看板与详情
aegis-os a2a board
aegis-os a2a show <task-id>
aegis-os top

board 会显示 task、state、from → to、age、flags、subject。input-required 会置顶并标记 BLOCKED；失去 assignee 的任务会标记 STALE。

如果使用自定义 --runtime-dir，所有 a2a / policy / memory revoke 命令都要传同一个 runtime 目录。

05 / REVOKE & AUDIT

撤销与防篡改哈希链审计

你可以直接在 Agent 对话中说“查看当前多 Agent 任务的子任务进展和审计记录”——Agent 调用 ipc_task_get / ipc_task_list 即可直接返回子任务树（subtasks）、关联的跨边界操作轨迹（audit_trace）以及 SHA-256 哈希链完整性校验结果（hash_chain_verified: true）。

若需随时收回已授予的会话租约（如 15 分钟 / 1 小时落盘租约或外网域名租约），可在 Aegis 控制台 (/aegis-cloud/dashboard) 或 边界审批台 (/approve) 的「我已授权的生效租约 (ACTIVE SESSION LEASES)」列表中直接点击 撤销 (Revoke) 按钮（调用 POST /v1/leases/revoke），租约将立即失效并记入哈希链审计账本。

若需查看并撤销一个 UOMP memory session：

aegis-os memory sessions
aegis-os memory revoke <session-id>

撤销后：

  • 下一个 memory 请求返回 401 SESSION_NOT_ACTIVE
  • 如果 session 绑定了 A2A task，task 会转为 input-required（标记 BLOCKED）
  • 审计账本会以防篡改哈希链（prev_hash → event_hash）永久记录 revoke 事件和 task id
aegis-os memory audit --limit 20
aegis-os a2a board

如果任务通过 gateway 进入终态（例如 tasks/cancel 或父任务级联取消），Aegis OS 会自动释放该任务绑定的所有文件锁（coord_claim）、撤销任务级租约，并调用 memory server 的 revoke-by-task 自动撤销关联的 memory sessions。

06 / LIFECYCLE

升级、崩溃恢复与卸载

1. 原地升级与配置同步

aegis-os upgrade 会自动识别当前安装来源（Homebrew、Cargo、本地源码或通过编译内置公钥 RELEASE_SIGNER 执行 ssh-keygen -Y verify 校验的官方签名发行版），原地升级后自动刷新 AGY / Claude Code / Codex / OpenCode 全局配置与现有 Shim，并将遗留 /tmp/aegis-os-runtime 指向无损迁移至 ~/.aegis。

# 检查版本与客户端配置漂移
aegis-os upgrade --check

# 原地升级并同步全局配置与 Shim（仅刷新配置可加 --refresh-only）
aegis-os upgrade
aegis-os upgrade --refresh-only

2. OrgVault 加密卷与崩溃孤儿影子恢复

默认情况下，所有未提交的 CoW 影子写入都通过 fsync 持久保存在 ~/.aegis 按组织隔离的 OS 加密卷 OrgVault 中。若终端或 Agent 进程异常退出，可查看并手动接管未提交的孤儿影子，或手动锁定/解锁加密卷：

# 检查各组织 OrgVault 状态（后端、挂载状态、密钥来源）及可恢复的孤儿影子
aegis-os vault status

# 接管上次异常退出的孤儿影子，或在跨会话时手动解锁/锁定加密卷
aegis-os vault recover --from-agent <agent-id>
aegis-os vault unlock
aegis-os vault lock

3. 外科手术式卸载

卸载时默认只移除 Aegis 注入的 Shim 与各客户端配置块，完整保留用户的其他个人配置以及 ~/.aegis 中的加密卷与未提交影子；仅在显式指定 --purge --yes 时才会在锁定卸载所有 OrgVault 后清除运行时数据与主密钥 KEK 材料（所有模式均支持 --dry-run 预览）：

# 仅移除 ~/.aegis/bin PATH Shim 与 shell PATH 块（保留 MCP / Hook）
aegis-os uninstall --shim-only

# 标准卸载：外科手术式移除 4 款客户端 Aegis 条目与 Shim（保留 ~/.aegis 加密卷）
aegis-os uninstall --dry-run
aegis-os uninstall

# 彻底销毁（含工作区 .agents/ 与 ~/.aegis 加密卷、KEK 密钥材料）
aegis-os uninstall --workspace-clean --purge --yes

07 / TROUBLESHOOT

故障排查

问题处理
客户端看不到 Aegis OS 工具运行 aegis-os doctor；重启客户端；检查 MCP 配置。
Agent 一直等待审批先看是否已自动打开同意页；没有就运行 aegis-os memory ui。CLI fallback：aegis-os memory pending，再 approve / deny。
端口 9374 被占用aegis-os memory stop；或 aegis-os memory setup claude --listen 127.0.0.1:9380。
同意页 9375 端口被占用运行 aegis-os memory ui --listen 127.0.0.1:9376 --url http://127.0.0.1:9374；或关闭占用 9375 的进程。
SESSION_NOT_ACTIVEsession 过期或被撤销；重新发起请求，或 aegis-os memory connect claude --scope notes/projects。
ACCESS_DENIEDkey/tag 不在批准范围；查看 aegis-os memory audit 和 consent request scope。
