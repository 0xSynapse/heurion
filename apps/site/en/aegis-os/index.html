FLAGSHIP 02 · RUST · TRANSACTIONAL AGENT OS

Aegis OS
Transactional multi-agent control plane

Aegis OS lets multiple coding agents (Claude Code, Codex, AGY) run safely in parallel: each agent gets its own CoW shadow workspace and kernel sandbox, collaborates through Google A2A, requests personal memory through UOMP, and every boundary crossing goes through task-scoped leases, approval, revocation, and audit.

Install to first task → Cloud Console & Pro Subscription → GitHub repository →

01 / ISOLATION

Isolation

One CoW shadow workspace per agent; macOS Seatbelt / Linux Bubblewrap sandboxing; host credentials and out-of-bound writes denied by default.

02 / COLLABORATION

Collaboration

Google A2A AgentCard, task lifecycle, peer registry, file claims, and the Live Collaboration Radar.

03 / CONSENT

Consent & Approvals

Boundary commits auto-open the web approval console and auto-resume once approved (or run aos approve); UOMP memory consent enforces tag/key scopes with full audit.

01 / INSTALL

Install Aegis OS

macOS and Linux are supported. Windows is not supported. After Homebrew installs the binary, run aegis-os install once to wire agy, claude, and codex.

# Option A: Homebrew (macOS & Linux)
brew tap heurion-org/aegis-os https://github.com/heurion-org/aegis-os.git
brew install aegis-os
aegis-os install

# Option B: One-line signed installer (automatically runs aegis-os install)
curl -fsSL https://heurion.org/aegis-cloud/install.sh | sh

# Verify
aegis-os doctor

Without Homebrew, run the one-line signed installer above or download the platform binary from GitHub Releases and run aegis-os install once.

02 / FIRST RUN

First run

01

Launch your agent in a project

Run claude, codex, or agy directly. Aegis OS hooks attach the runtime and start silently in Free Local CoW mode; to offload builds to a 64GB zero-local-load Cloud Sandbox, open the Cloud Console & Billing Center anytime.

02

Work in isolation, approve commits in 1 click

Agent writes and tests execute inside the CoW shadow workspace with 0 prompts; when workspace_commit crosses the host boundary, Aegis OS auto-opens the approval console and auto-resumes once approved (or run aos approve in terminal).

03

Approve memory access explicitly

Agents request notes through UOMP. Aegis OS opens a local consent page automatically; select the tags / keys to grant, then Allow or Deny. No second terminal is required, and an agent cannot approve its own request.

04

Revoke and audit at any time

aegis-os memory revoke <session-id> removes access immediately; a bound A2A task moves to input-required. Every allow/deny is recorded in aegis-os memory audit.

03 / CORE COMMANDS

Common commands

# Install check & live multi-agent radar
aegis-os doctor
aegis-os top

# Boundary approval (auto-detects Local/Cloud & latest pending escalation; alias: aos approve)
aegis-os approve

# Memory: import, client config, local server
aegis-os memory setup claude --vault ~/Notes
aegis-os memory ui
aegis-os memory pending
aegis-os memory approve <request-id>
aegis-os memory audit
aegis-os memory revoke <session-id>

# Multi-agent: A2A task and board
aegis-os ipc request --to worker --subject "Review auth" --message "Read the auth module"
aegis-os a2a board
aegis-os a2a show <task-id>

# Task-scoped lease (advanced)
aegis-os policy lease --action-pattern workspace_commit --ttl-secs 3600 --task-id <task-id>

If you use a custom --runtime-dir, pass the same runtime directory to a2a board, a2a show, and memory revoke.
