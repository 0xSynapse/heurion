Aegis OS
Local multi-agent control plane

Aegis OS lets multiple coding agents run safely on one machine: each agent gets its own CoW workspace, collaborates through Google A2A, requests personal memory through UOMP, and every boundary crossing goes through task-scoped leases, approval, revocation, and audit.

Install to first task → GitHub repository →

01 / ISOLATION

Isolation

One CoW shadow workspace per agent; macOS Seatbelt / Linux Bubblewrap sandboxing; host credentials and out-of-bound writes denied by default.

02 / COLLABORATION

Collaboration

Google A2A AgentCard, task lifecycle, peer registry, file claims, and the Live Collaboration Radar.

03 / CONSENT

Consent

UOMP memory consent: tag/key scope, time limits, revocation; high-sensitivity items require per-key approval; a local trusted consent UI opens automatically, so you never need a second terminal; every allow/deny is audited.

INSTALL

Install Aegis OS

macOS and Linux are supported. Windows is not supported. The installer wires Aegis OS into agy, claude, and codex.

# Homebrew
brew tap heurion-org/aegis-os https://github.com/heurion-org/aegis-os.git
brew trust heurion-org/aegis-os
brew install aegis-os

# Verify
aegis-os --version
aegis-os doctor

Without Homebrew, download the platform binary from GitHub Releases or build from source. If the client wiring was skipped, run aegis-os install once.

FIRST RUN

First run

01

Launch your agent in a project

Run claude, codex, or agy directly. Aegis OS hooks attach the runtime; the first run asks you to choose Local (free, local) or Cloud (Aegis Cloud).

02

Work inside an isolated workspace

Agent writes land in a CoW shadow workspace first; workspace_commit merges them back to the host. File claims prevent silent overwrites when agents run in parallel.

03

Approve memory access explicitly

Agents request notes through UOMP. Aegis OS opens a local consent page automatically; select the tags / keys to grant, then Allow or Deny. No second terminal is required, and an agent cannot approve its own request.

04

Revoke and audit at any time

aegis-os memory revoke <session-id> removes access immediately; a bound A2A task moves to input-required. Every allow/deny is recorded in aegis-os memory audit.

CORE COMMANDS

Common commands

# Install check
aegis-os doctor

# Memory: import, client config, local server
aegis-os memory setup claude --vault ~/Notes

# Consent UI (usually opens automatically; use this to open it manually)
aegis-os memory ui

# CLI fallback
aegis-os memory pending
aegis-os memory approve <request-id>
aegis-os memory audit
aegis-os memory revoke <session-id>

# Multi-agent: A2A task and board
aegis-os ipc request --to worker --subject "Review auth" --message "Read the auth module"
aegis-os a2a board
aegis-os a2a show <task-id>

# Task-scoped lease (advanced)
aegis-os policy lease --action-pattern workspace_commit --ttl-secs 3600 --task-id <task-id>

If you use a custom --runtime-dir, pass the same runtime directory to a2a board, a2a show, and memory revoke.
