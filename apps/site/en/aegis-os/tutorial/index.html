AEGIS OS · TUTORIAL · 2026

Install to your first
multi-agent task

This tutorial is for a first-time Aegis OS user. By the end you will have an isolated agent workspace, an approved memory access, a revocable A2A task, and an audit trail you can inspect.

Estimated time: 10–15 minutes. macOS / Linux only; Windows is not supported.

0. Prepare 1. Install 2. Connect an agent 3. Memory consent 4. Multi-agent / A2A 5. Revoke and audit 6. Troubleshooting

00 / PREPARE

Prepare

You need:

  • macOS or Linux terminal
  • Homebrew
  • A coding agent: Claude Code, OpenCode, Codex CLI, Hermes, or AGY
  • A Markdown / Obsidian vault (optional, for memory consent)

Windows is not supported. Do not put real production credentials in the sample workspace; use a local temporary project for this tutorial.

01 / INSTALL

Install Aegis OS

# Add the Heurion tap and install
brew tap heurion-org/aegis-os https://github.com/heurion-org/aegis-os.git
brew trust heurion-org/aegis-os
brew install aegis-os

# Wire AGY / Claude Code / OpenCode / Codex / Hermes (pass --enforce for OS-enforced wrapper shims)
aegis-os install

# Verify & 5-second local security checkup
aegis-os --version
aegis-os doctor
aegis-os audit-me

After Homebrew installs the binary, run aegis-os install once to wire Aegis OS into agy, claude, opencode, codex, and hermes; doctor should then pass.

Without Homebrew: download the platform binary from GitHub Releases or build with cargo install --path crates/aos-cli. Then run aegis-os install.

02 / FIRST RUN

Connect an agent

Enter a project directory and launch in either Advisory plugin mode or Enforced parent-process OS sandbox mode:

# Option A (Advisory productivity rails): launch directly
claude
opencode
codex
agy

# Option B (Enforced OS kernel boundary): spawn inside bwrap / Seatbelt via aegis-os run
aegis-os run -- claude
aegis-os run -- opencode

Aegis OS hooks attach the runtime automatically. It starts silently in Free Local CoW mode by default, and you can switch to Cloud mode anytime:

ModeWhat it means & entry point
LocalFree local mode (default): CoW shadow workspace + native OS sandbox, ready immediately with zero setup prompts.
CloudRemote 64GB Linux btrfs runtime (0% local CPU/RAM load): supports both a free tier (aegis-os cloud up) and Pro ($29/mo, 8 parallel Agents). Open the Aegis Cloud Console (/aegis-cloud/dashboard) → or run aegis-os cloud subscribe --plan pro --wait.

You can switch later by telling the agent “switch to Local mode” or “switch to Cloud mode”.

Verify isolation & boundary approval

In daily work you never need to run aegis-os CLI subcommands manually—just instruct your coding agent in natural language:

# Inside your Claude / Codex / AGY conversation:
Update the README title, inspect the diff, and commit it back to the host repo

The agent edits inside its CoW shadow workspace first (fs_edit / workspace_diff) without touching the host directory. When the agent calls workspace_commit, Aegis OS prompts inline or auto-opens the keyless web approval console (/approve and /aegis-cloud/dashboard—zero manual API key entry on local workstations, or email lookup for cloud subscriptions), serializes concurrent commits via the host commit lock, and runs verify_cmd before landing:

  • Inline Colored Unified Diff Preview (Inspect Diff): Expand the syntax-highlighted Unified Diff (GET /v1/approvals/diff) and changed file list directly inside the approval card before deciding—no terminal context switching required.
  • Cryptographic TOCTOU-Pinned Approval (Approve Once · SHA-256 Pinned): One-shot approval pins the lease to the exact SHA-256 digest of the canonical diff and commit flags (sha256:<evidence_hash>, bounded to 15m). If an agent alters even a single byte after you click approve, the commit is blocked immediately.
  • Batched Single-Card Sensitive Approval & Bounded TTL Leases: Commits touching multiple sensitive build or hook files (Cargo.toml, package.json, Makefile) are consolidated into a single workspace_commit_sensitive card, alongside optional 15-minute or 1-hour session leases for routine text commits.

On headless SSH sessions you can also run aegis-os approve (alias: aos approve).

03 / MEMORY CONSENT

Memory consent: only the approved scope

UOMP is the memory consent protocol enforced by Aegis OS. First write the client bridge profile and import notes:

aegis-os memory setup claude --vault ~/Notes

This command:

  • imports Markdown notes (base tag notes by default; use --tag)
  • starts the local memory server in the background (default 127.0.0.1:9374)
  • writes the Claude Desktop / Cursor / OpenCode MCP config
  • issues no token and grants no access

Restart the client, then ask the agent to read notes:

# In Claude / Cursor / OpenCode
List the notes under notes/projects

The first tool call creates a consent request. Aegis OS opens a local consent page automatically (127.0.0.1:9375); select the tags / keys to grant, then click Allow selected. No second terminal is required.

# If the browser did not open automatically, start the consent UI manually
aegis-os memory ui

# CLI fallback
aegis-os memory pending
aegis-os memory approve <request-id>

The page shows the request id, agent, task id (if any), session id, and expiry. After approval the current call continues; a denial returns an error.

High-sensitivity data is not opened by a tag scope. The consent page lists specific keys separately, and you must select each key; an agent cannot approve its own request.

Verify

aegis-os memory sessions
aegis-os memory audit --limit 20

You should see the session scope, expiry, and allow / deny audit events.

04 / MULTI-AGENT

Multi-agent / A2A

Aegis OS uses Google A2A as the agent-to-agent collaboration bus. Collaboration is Agent-First (zero manual CLI commands required)—simply ask your lead agent (agy, claude, or codex) in natural language:

# Inside your lead agent conversation:
Delegate an auth module security review to claude-code in the other window, claim the router files I am editing, and merge once it finishes

Under the hood, the runtime coordinates the agents automatically over MCP:

  • Task-Bound Glob File Claims & Auto-Release (coord_claim): Agents claim target paths before editing (with 2D NFA + live file-tree glob intersection detection for patterns like src/** vs. src/auth/*.rs, plus coordination_warning alerts if a sandboxed proc_exec script touches peer-claimed files). Claims are released automatically upon workspace_commit or task completion.
  • Hierarchical A2A Subtask Graph & Cascade Cancellation (ipc_request): Tasks support parent_task_id hierarchies and depends_on DAG dependencies. Canceling a parent task recursively cancels all non-terminal child tasks and revokes their bound claims and leases.
  • Zero-Polling Blocking Wakeup (ipc_wait): Alongside piggybacked _aegis_inbox notifications on every tool call, clients without lifecycle hooks (such as Codex CLI) can call ipc_wait to block until a peer replies or a task transitions state.

Task-scoped leases & optional CLI board

When you approve a task's escalation in the web approval console (/approve), the issued lease is bound to that task_id ("kind": "task_scoped"). When the task reaches a terminal state, its lease is revoked automatically; an agent cannot reuse task A's lease for task B.

If you want a read-only terminal view of live tasks across your workstation, you can optionally run:

# Optional read-only terminal inspectors
aegis-os a2a board
aegis-os a2a show <task-id>
aegis-os top

board shows task, state, from → to, age, flags, and subject. input-required is pinned with BLOCKED; a task whose assignee disappeared is marked STALE.

If you use a custom --runtime-dir, pass the same runtime directory to all a2a / policy / memory revoke commands.

05 / REVOKE & AUDIT

Revoke and hash-chained audit

You can ask your agent directly in chat to “show the subtask status and audit trail for the current A2A task”—the agent calls ipc_task_get / ipc_task_list to inspect the child subtasks, the task-correlated audit_trace, and cryptographic SHA-256 hash-chain verification (hash_chain_verified: true).

To revoke an active session lease (such as a 15-minute or 1-hour commit lease or a domain-scoped egress lease) at any time, click Revoke (撤销) next to the lease in the Active Session Leases panel of the Aegis Console (/aegis-cloud/dashboard) or Approval Console (/approve) (backed by POST /v1/leases/revoke). Revocation takes effect immediately and is recorded in the hash-chained audit ledger.

To inspect and revoke a UOMP memory session from the terminal:

aegis-os memory sessions
aegis-os memory revoke <session-id>

After revocation:

  • the next memory request returns 401 SESSION_NOT_ACTIVE
  • if the session is bound to an A2A task, the task moves to input-required (marked BLOCKED)
  • the tamper-evident hash-chained audit ledger (prev_hash → event_hash) records the revoke event and task id
aegis-os memory audit --limit 20
aegis-os a2a board

If a task reaches a terminal state through the gateway (for example tasks/cancel or parent cascade cancellation), Aegis OS automatically releases all task-bound file claims (coord_claim), revokes task-scoped leases, and calls the memory server's revoke-by-task endpoint to revoke that task's memory sessions.
