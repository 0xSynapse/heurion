\begin{abstract}
Autonomous large language model (LLM) agents often edit documents via shell scripts and post-hoc file checks. In clinical research authoring, this workflow risks corrupting Office Open XML (\texttt{.docx}/\texttt{.pptx}) formatting, overwriting concurrent human edits, inserting unverified bibliographic IDs (DOIs/PMIDs), exposing Protected Health Information (PHI), and repeating guard failures across sessions.

We present \textbf{Heurion 2.0}, a clinical authoring platform combining a \emph{Contract-Guarded Dual-Surface Architecture} with a \emph{Three-Layer Self-Evolving Memory System}. A shared CRDT core (ProseMirror + Yjs) with stable block IDs projects a rich-text editor for clinicians and a guarded Annotated Markdown surface for AI agents with per-turn undo and original-slice OOXML export. Pre-write guards block unregistered citations, a two-stage PHI funnel pairs checksum/regex validators with a pre-masked local $1.5\text{B}$ model (\texttt{qwen2.5:1.5b}) and symbolic output filtering, and runtime guard/revert signals feed a utility-ranked procedural memory store isolated from declarative preferences. Across $1,286$ analysed live LLM turns on $10$ PMC manuscripts and $710$ guard test records, Heurion 2.0 achieved: (1) comparable completion ($93.8\%$ vs.\ $95.1\%$, $p=1.00$), $0$ vs.\ $4$ content-corrupted untouched paragraphs ($p=0.125$), and $100\%$ ($9/9$ vs.\ $0/9$, $p<0.0001$) comment resolution in \texttt{.docx} editing ($162$ turns); (2) $98.6\%$ ($710/720$) synthetic PHI recall ($100\%$ on $600$ structured spans in Stage~1; $91.7\%$ on $120$ narrative spans in Stage~2) and $0/30$ unconfirmed destructive tool executions ($45$ turns total); and (3) in a pre-specified $8$-seed, $5$-session ablation ($1,079$ turns), a directional $49\%$ reduction in guard rejections on the primary mixed model ($\text{RR}=0.51$, Holm $p=0.1089$; NB2 sensitivity $\text{RR}=0.50$, Holm $p=0.0269$) and a $37\%$ reduction in total execution signals ($\text{RR}=0.63$, Holm $p=0.0011$).
\end{abstract}

\section{Introduction}
\label{sec:intro}

Clinical and biomedical research workflows require high standards of traceability, structural fidelity, and regulatory compliance. A single clinical study typically spans patient longitudinal record curation, cohort screening, biostatistical modeling (e.g., baseline Table~1 generation, Kaplan--Meier survival curves, Cox proportional hazards regression, CONSORT flow diagrams), and the iterative authoring of peer-reviewed manuscripts (\texttt{.docx}) and academic presentation decks (\texttt{.pptx}) \cite{schulz2010consort,vandenbroucke2007strobe}. While recent agentic systems have demonstrated strong capabilities in code generation \cite{yang2024sweagent,wang2024openhands} and open-domain literature synthesis \cite{shao2024storm,skarlinski2024paperqa2}, deploying autonomous agents into clinical research environments exposes four architectural barriers:

\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{The Free-Form File Mutation Trap:} Conventional script-based document agents treat \texttt{.docx} and \texttt{.pptx} files as opaque disk artifacts manipulated via generated Python scripts (e.g., \texttt{python-docx}) followed by post-hoc quality checks. In practice, script-based rewrites can strip publisher XML attributes, lose paragraph addressing identifiers (\texttt{w14:paraId}) during LibreOffice layout passes, suffer from punctuation/whitespace reproduction drift in full-block replacements, and cannot selectively undo an AI turn once a human co-author makes concurrent edits.
  \item \textbf{Citation Fabrication and Ungrounded Clinical Claims:} LLMs frequently hallucinate plausible-looking Digital Object Identifiers (DOIs), PubMed IDs (PMIDs), or numerical hazard ratios ($HR$) and $p$-values \cite{ji2023survey,walters2023fabrication,bhattacharyya2023hallucination}. Post-hoc prompting alone cannot guarantee that every inline reference corresponds to a verified bibliographic record or that statistical assertions match the cited source text.
  \item \textbf{Patient Privacy (PHI) Exposure and Permission Asymmetry:} Clinical investigators work with raw electronic medical records containing Protected Health Information (patient names, national ID numbers, admission codes, phone numbers) \cite{stubbs2015deid,norgeot2020philter}. Passing unredacted records to external LLMs conflicts with health-data protection law in both jurisdictions we target: China's Personal Information Protection Law (PIPL) classifies medical and health information as sensitive personal information that may be processed only for a specific purpose, with separate consent and strict protective measures, and imposes additional conditions on cross-border transfer \cite{pipl2021}; the U.S. HIPAA Privacy Rule restricts disclosure of PHI unless it is de-identified, for example by removing the 18 Safe Harbor identifiers \cite{hipaa1996}. Conversely, granting agents unrestricted database or shell access creates privilege-escalation and indirect prompt-injection risks \cite{greshake2023injection}.
  \item \textbf{Cross-Session Amnesia and Memory Pollution:} When an agent encounters a structural guard rejection (e.g., attempting to overwrite a human-edited block or inserting an unregistered citation) or when a clinician reverts an AI turn, stateless agents repeat the same operational failure in subsequent turns. Naively appending all historical observations into a single flat memory pool mixes subjective user writing preferences with hard operational constraints, exhausting context budgets with low-utility noise \cite{shinn2023reflexion,packer2023memgpt}.
\end{enumerate}

\subsection{Why Script-and-Audit File Mutation Fails in Collaborative Authoring}
When general-purpose coding agents operate inside a workspace shell, they typically invoke Python scripts (\texttt{python-docx} or XML manipulators) to unpack, mutate, and repackage \texttt{.docx} archives on disk, optionally pairing edits with a post-turn audit script that checks text survival rates, paragraph drift, or DOI validity. Collaborative clinical authoring exposes three structural limitations in this ``script-and-audit'' paradigm:
\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{AI Editing Can Disrupt Document Structure:} When an agent edits a manuscript via ad-hoc scripts or whole-block re-serialization, it risks altering the underlying OOXML structure---stripping journal-template paragraph and run properties (\texttt{<w:pPr>}, \texttt{<w:rPr>}), breaking list numbering chains and multi-row table merges, detaching inline review comments and track-changes spans, and losing paragraph identifiers (\texttt{w14:paraId}) across layout passes.
  \item \textbf{Risk of Overwriting Concurrent Human Edits:} Because script-based agents read a file snapshot, rewrite whole paragraphs or sections, and write the file back, any concurrent edits made by the clinician mid-turn (such as inserting a clinical caveat in the same paragraph, adjusting a statistic, or attaching a comment) can be overwritten. Reconciling an AI-rewritten file with concurrent browser edits via post-hoc three-way merges is brittle.
  \item \textbf{Post-Hoc Auditing Cannot Prevent Destructive Writes:} Auditing \emph{after} the write occurs only after mutation: once a script has altered document formatting or overwritten a co-author's edit, a post-hoc check can only flag the discrepancy or trigger a coarse file-level rollback that discards the entire turn. Preventing structural corruption and human-edit loss requires replacing free-form file mutation with a shared, fine-grained collaborative data structure and pre-write structural guards.
\end{enumerate}

\subsection{The Heurion 2.0 Architecture and Contributions}
\textbf{Heurion 2.0} shifts from \emph{post-hoc file auditing} to \emph{pre-write structural contracts over a shared CRDT core}, coupled with a \emph{signal-driven self-evolving execution harness}. Our primary contributions are fourfold:

\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Contract-Guarded Dual-Surface CRDT Engine (Section~\ref{sec:dualsurface}):} We design a unified ProseMirror + Yjs document core \cite{shapiro2011crdt,kleppmann2019localfirst} with persistent block addressing (\texttt{\{\#id\}}), node-level optimistic concurrency control (\texttt{base\_rev}), minimal-diff XML fragment updates that preserve inline marks and comment anchors, per-turn selective CRDT undo (\texttt{revertTurn}), and raw-slice OOXML patch export (\texttt{node\_src}) that writes back original XML bytes for unmodified blocks.
  \item \textbf{Pre-Write Citation and Two-Stage Neuro-Symbolic PHI Guards (Section~\ref{sec:evidence}):} We enforce a syntactic pre-write ban on raw inline DOIs/PMIDs, requiring registration via Crossref, PubMed, and OpenAlex into atomic citation nodes (\texttt{[@c:id]}), and design a two-stage PHI redaction cascade that pairs sub-millisecond checksum/regex validators with a pre-masked local $1.5\text{B}$ small language model (\texttt{qwen2.5:1.5b}) and symbolic output filtering to redact both structured identifiers and unstructured clinical narratives within the local loopback boundary. For system completeness, we also outline our multi-agent claim verification pipeline and sandboxed biostatistical tools (which are not quantitatively evaluated in this study).
  \item \textbf{Three-Layer Self-Evolving Agent Architecture (Section~\ref{sec:evolution}):} We introduce a hierarchical adaptation loop comprising (Layer~1) side-effect-free pre-flight validation probes (\texttt{doc\_validate} / \texttt{dry\_run}), (Layer~2) a dual-track memory architecture that physically separates human-approved declarative preferences from runtime-crystallized procedural strategies ranked by a cue-based utility score under a fixed prompt budget, and (Layer~3) background meta-strategy distillation into dynamic agent profile overlays.
  \item \textbf{CI-Enforced Human-AI Permission Symmetry (Section~\ref{sec:parity}):} We establish, and mechanically check via an automated parity test over the router table, an architectural invariant across all platform endpoints: every REST capability either maps 1-to-1 to an in-process Model Context Protocol (MCP) \cite{anthropic2024mcp} tool executing under the user's exact RBAC identity, or is explicitly justified in a restricted exclusion set, with high-risk mutations gated by human-only confirmation cards.
\end{itemize}

Heurion 2.0 is governed by three formal architectural invariants that enforce pre-write document integrity, human-AI permission symmetry, and memory orthogonality:

\begin{invariant}[Pre-Write Structural Safety]
\label{inv:prewrite}
Let $S_r$ denote the CRDT document state at revision $r$, and let $\mathcal{O} = \{o_1, \dots, o_k\}$ be a batch of structured edit operations submitted by an AI turn $t$ against base revision $r_{\text{base}} \le r$. Let $\Delta_{\text{user}}(r_{\text{base}}, r)$ be the set of block IDs modified by human actors in $(r_{\text{base}}, r]$, $\mathcal{P}_{\text{sugg}}(S_r)$ be the set of blocks holding unresolved clinician track-changes suggestions, $\text{Anchors}(b)$ be the set of open review-comment anchors attached to block $b$, and $\mathcal{R}_{\text{cite}}(S_r)$ be the set of verified citation identifiers registered in the document store. The state transition $\mathcal{T}(S_r, \mathcal{O}, r_{\text{base}})$ commits if and only if every $o_i \in \mathcal{O}$ with target block $b = \text{target}(o_i)$ satisfies all four pre-write conditions:
\begin{equation}
\begin{aligned}
  \text{BlockMut}(o_i) &\implies b \notin \Delta_{\text{user}}(r_{\text{base}}, r) \cup \mathcal{P}_{\text{sugg}}(S_r), \\
  \text{ReplaceText}(o_i) &\implies \bigl|\text{Matches}\bigl(\text{find}(o_i),\, S_r[b]\bigr)\bigr| = 1 \;\land\; b \notin \mathcal{P}_{\text{sugg}}(S_r), \\
  \text{Anchors}(S_r[b]) &\subseteq \text{Anchors}\bigl(o_i(S_r[b])\bigr) \cup \text{DropAnchors}(o_i), \\
  \text{Cites}(o_i) &\subseteq \mathcal{R}_{\text{cite}}(S_r) \;\land\; \text{RawCitePattern}(o_i) = \emptyset.
\end{aligned}
\end{equation}
Otherwise, the entire batch $\mathcal{O}$ is atomically rejected prior to mutating $S_r$, returning a structured diagnostic code (\texttt{conflict\_user\_edited}, \texttt{pending\_suggestion}, \texttt{text\_not\_found}, \texttt{ambiguous\_match}, \texttt{anchor\_has\_open\_comments}, or \texttt{citation\_not\_registered}) and the current block snapshot.
\end{invariant}

\begin{invariant}[Human-AI Permission Symmetry]
\label{inv:parity}
Let $\mathcal{E}_{\text{REST}}$ be the set of all HTTP API routes exposed to the web user interface, and let $\mathcal{E}_{\text{MCP}}$ be the set of Model Context Protocol (MCP) tools exposed to the AI agent. Every route $e \in \mathcal{E}_{\text{REST}}$ satisfies the disjoint partition:
\begin{equation}
  \mathcal{E}_{\text{REST}} = \phi(\mathcal{E}_{\text{MCP}}) \sqcup \mathcal{E}_{\text{NOT\_FOR\_AI}},
\end{equation}
where $\phi: \mathcal{E}_{\text{MCP}} \to \mathcal{E}_{\text{REST}}$ is an in-process Loopback dispatcher that executes under the authenticated user's exact session token and tenant isolation context, and $\mathcal{E}_{\text{NOT\_FOR\_AI}}$ is an explicitly audited set of human-only lifecycle endpoints (e.g., credentials, high-risk confirmation approval).
\end{invariant}

\begin{invariant}[Declarative-Procedural Memory Orthogonality]
\label{inv:memory}
Let $\mathcal{M}_D$ denote the declarative memory store (subjective authoring preferences, stylistic conventions, domain terminology) and $\mathcal{M}_P$ denote the procedural harness store (operational guard avoidance rules and subagent delegation policies). Updates to $\mathcal{M}_D$ require explicit human confirmation ($\text{status} \in \{\texttt{candidate} \xrightarrow{\text{human}} \texttt{confirmed}\}$), whereas $\mathcal{M}_P$ evolves autonomously from deterministic runtime execution signals $\Sigma_{\text{exec}}$ without polluting $\mathcal{M}_D$ or requiring manual administrative curation.
\end{invariant}

\section{Dual-Surface Co-Editing and Original-Slice Document Engine}
\label{sec:dualsurface}

How can autonomous AI agents edit complex Word (\texttt{.docx}) manuscripts and PowerPoint (\texttt{.pptx}) presentation decks without corrupting journal-template formatting or overwriting concurrent human edits? A central architectural observation in Heurion 2.0 is that Office Open XML (\texttt{.docx} and \texttt{.pptx}) files are delivery formats, not collaborative editing data structures. When an agent edits a \texttt{.docx} file on disk via a Python script while a human views the document in a browser, the two actors operate on divergent state representations. Heurion 2.0 eliminates this divergence by replacing direct file scripting with a Contract-Guarded Dual-Surface CRDT Engine \cite{shapiro2011crdt,kleppmann2019localfirst}.

\subsection{Shared CRDT Core with Lifecycle-Stable Block Addressing}
In Heurion 2.0, every manuscript and presentation deck resides in a server-authoritative Yjs CRDT document (\texttt{Y.Doc}) backed by SQLite state snapshots and an append-only revision log (\texttt{doc\_commits}). Every block-level ProseMirror node (heading, paragraph, list item, table, figure, or slide element) is assigned a short, lifecycle-stable identifier (\texttt{attrs.id}, rendered as \texttt{\{\#id\}}). When a human splits a paragraph or pastes content in the browser, the server-side \texttt{flush()} handler automatically detects duplicate or missing block IDs and assigns fresh unique IDs inside a system CRDT transaction, ensuring the addressing space remains bijective.

From this single CRDT core, Heurion 2.0 projects two synchronized surfaces:
\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Human Surface:} A real-time collaborative ProseMirror rich-text editor (for manuscripts) and an interactive 16:9 SVG/HTML slide canvas (for decks) synchronized via WebSocket (\texttt{y-protocols/sync}).
  \item \textbf{Agent Surface:} A compact \emph{Annotated Markdown} view generated on demand via \texttt{doc\_read} and \texttt{slide\_read}. Each block is suffixed with its stable address \texttt{\{\#id\}}, inline citations are rendered as atomic tokens \texttt{[@c:cite\_id]}, figures as \texttt{![alt](asset:id)}, and active inline review comments as \texttt{\{\#c:comment\_id\}}.
\end{enumerate}

\subsection{Node-Level Conflict Guards and Minimal-Diff Fragment Updates}
To prevent an AI turn in Heurion 2.0 from overwriting concurrent human edits, every \texttt{doc\_edit} call specifies the \texttt{base\_rev} read by the agent. As formalized in Invariant~\ref{inv:prewrite}, the platform queries the \texttt{node\_changes} index for all blocks modified by human actors since \texttt{base\_rev}:
\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Block-Level Structural Operations (\texttt{replace\_block}, \texttt{delete}):} If a target block $b \in \Delta_{\text{user}}(r_{\text{base}}, r)$, the operation is rejected with error code \texttt{conflict\_user\_edited}, returning the human's latest block markdown so the agent can adapt. Similarly, blocks carrying unresolved track-changes suggestions ($b \in \mathcal{P}_{\text{sugg}}(S_r)$) are protected by the \texttt{pending\_suggestion} guard, and blocks holding open review comments require either preserving the comment anchors or explicitly declaring \texttt{drop\_anchors} (\texttt{anchor\_has\_open\_comments}).
  \item \textbf{Substring Replacement (\texttt{replace\_text}):} For surgical phrase edits within a paragraph, the literal \texttt{find} substring acts as its own optimistic concurrency guard: if the human edited a different sentence in the same paragraph, \texttt{find} still matches uniquely and succeeds; if the human altered the target phrase itself or if \texttt{find} matches multiple occurrences, validation fails cleanly with \texttt{text\_not\_found} or \texttt{ambiguous\_match}.
  \item \textbf{Mark-Preserving Minimal Diffs:} Notably, \texttt{replace\_text} does not re-parse the paragraph from plain text (which would destroy inline bold/italic spans, \texttt{[@c:id]} citation nodes, and comment highlights outside the matched range). Instead, it locates the character offsets $[s, e)$ in the ProseMirror node's flattened text stream and replaces only that slice, after which \texttt{writeFragment} updates only the modified XML children between the common prefix and suffix in the underlying \texttt{Y.XmlFragment}.
\end{itemize}

\subsection{Per-Turn Selective Undo in CRDT Space (\texttt{revertTurn})}
In collaborative scientific writing, a researcher may ask the AI to revise three sections, continue manually editing Section~2, and subsequently decide to undo the AI's changes. Global linear undo (\texttt{Ctrl+Z} or version rollback) would destroy the researcher's manual edits in Section~2.

Heurion 2.0 solves this via a two-tier \emph{Per-Turn Selective Undo} mechanism (\texttt{revertTurn}):
\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{In-Memory CRDT Origin Tracking:} When an AI turn $t$ commits changes to document $d$, the runtime binds a dedicated \texttt{ServerOrigin} object $o_t = \{\texttt{server}: \text{true}, \texttt{actor}: \texttt{'ai'}, \texttt{turnId}: t\}$ and attaches a scoped \texttt{Y.UndoManager} configured with $\texttt{trackedOrigins} = \{o_t\}$. Invoking \texttt{revertTurn(d, t)} executes \texttt{um.undo()} solely on the CRDT items inserted or deleted under origin $o_t$, leaving concurrent human character insertions---even within the same paragraph---intact.
  \item \textbf{Persistent Node-Level Fallback across Server Restarts:} Before turn $t$'s first write, the runtime persists the pre-turn Yjs state vector in \texttt{turn\_doc\_bases}. If the server restarts before \texttt{revertTurn} is invoked, the engine reconstructs the pre-turn document tree, computes the per-block diff against turn $t$'s recorded \texttt{node\_changes}, reverts all AI-modified blocks untouched by the user since $r_{\text{min}}(t)$, and safely skips blocks subsequently edited by the user (returning their IDs in \texttt{skipped}).
\end{enumerate}

\subsection{Original-Slice OOXML Patch Export}
Clinical manuscripts are frequently imported from journal-specific Word templates containing custom styles, headers/footers, macros, and embedded vector objects. During \texttt{.docx} or \texttt{.pptx} import, Heurion 2.0 stores the original archive in \texttt{doc\_packages} and records the raw XML slice (\texttt{<w:p>} or \texttt{<w:tbl>}) of every imported block in \texttt{node\_src} keyed by block ID. Upon export (\texttt{docx-export.ts}, \texttt{pptx-export.ts}), any block whose ProseMirror node is structurally equal (\texttt{node.eq(baselineNode)}, meaning its text, inline formatting marks, and attached comment range markers are unchanged) to its imported baseline is written back using its exact original \texttt{node\_src} XML bytes; only blocks whose text or inline comment/mark structure was mutated during the session are re-serialized, preserving paragraph properties (\texttt{<w:pPr>}), run fonts, and paragraph identifiers (\texttt{w14:paraId}) from the original template.

\section{Citation-Grounded Evidence Loop and Privacy-Preserving Clinical Pipeline}
\label{sec:evidence}

How can a clinical authoring platform prevent LLM citation fabrication while protecting patient privacy (PHI) in medical records? Heurion 2.0 addresses both requirements through deterministic pre-write syntactic guards and a two-stage neuro-symbolic PHI redaction funnel.

\subsection{Syntactic Citation Guard and Atomic Citation Nodes}
To prevent fabricated references from entering manuscript text, Heurion 2.0 blocks agents from writing raw bibliographic identifiers or hand-numbered brackets in prose. During pre-write validation in \texttt{OpService}, every candidate text string is scanned against structural regular expressions detecting bare DOIs (\texttt{10.\textbackslash d\{4,9\}/\dots}), bare PMIDs (\texttt{PMID:\textbackslash s*\textbackslash d+}), or unlinked reference markers. Any violation triggers \texttt{citation\_not\_registered} before modifying the document.

Instead, the agent must invoke \texttt{insert\_citation}, which queries live metadata APIs (Crossref, NCBI PubMed E-utilities, and OpenAlex), verifies the record's existence, stores the canonical metadata (authors, title, journal, year, volume, pages, DOI/PMID) in the document's \texttt{citations} table, and returns a registered token \texttt{[@c:cite\_id]}. In ProseMirror, \texttt{[@c:cite\_id]} is parsed into an atomic inline node (\texttt{atom: true}) that dynamically numbers itself according to citation order and automatically compiles the terminal References section.

\subsection{System Context: Claim Verification and Biostatistical Sandbox}
In addition to the pre-write citation guard evaluated in Section~\ref{sec:evaluation}, the platform includes a multi-agent claim verification service (\texttt{ClaimService.verify}) and a sandboxed biostatistical execution toolchain (included here for architectural context; clinician-graded evaluation of these modules is left to future work). Briefly, \texttt{verify\_claims} segments manuscript blocks into sentences, retrieves PubMed abstracts and available PubMed Central (PMC) full texts for cited \texttt{[@c:cite\_id]} records, and classifies quantitative assertions into four verdicts (\texttt{supported}, \texttt{contradicted}, \texttt{unsupported}, or \texttt{uncited\_stat}), attaching problematic claims as inline ProseMirror review comments. For statistical analysis, computation is delegated to isolated Python/R tools (\texttt{biostatistician} subagent) rather than free-text LLM arithmetic.

\subsection{Multi-Tenant PHI Redaction Funnel}
To bridge clinical data management and manuscript authoring without exposing patient identities \cite{stubbs2015deid,norgeot2020philter,presidio2021}, Heurion 2.0 enforces four privacy safeguards:
\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Per-Tenant Database Isolation \& Envelope Encryption:} Each organization tenant operates on a physically isolated SQLite database file (\texttt{tenants/<org\_id>/platform.db}) with per-tenant Data Encryption Keys (DEKs) wrapped by a master Key Encryption Key (KEK).
  \item \textbf{Two-Stage Neuro-Symbolic PHI Funnel (\texttt{phi-scan.ts}):} Using an external cloud LLM to inspect raw clinical text for PHI creates a privacy paradox: sending unredacted patient records to a third-party API in order to redact them already violates tenant data-residency boundaries. Conversely, running a frontier-scale $70\text{B}+$ parameter model on-premise imposes high GPU requirements for clinical research teams. Heurion 2.0 addresses this trade-off through a task-decomposed, two-stage neuro-symbolic funnel that operates within the local environment:
  \begin{enumerate}[leftmargin=1.5em,itemsep=1pt]
    \item \emph{Stage~1 --- Sub-Millisecond Deterministic Checksum \& Subtype Rules (\texttt{scanPhi}/\allowbreak\texttt{redactPhi}):} Deterministic rules execute first ($0.011\,\text{ms}$ per note) to validate and mask mathematically structured or field-labeled identifiers: 18-digit national IDs (ISO~7064 MOD~11-2 checksum + calendar bounds), settlement/bank cards (ISO/IEC~7812 industry prefix + Luhn mod-10 checksum with DOI/URL boundary exclusion), 11-digit mobile numbers, medical record numbers, and co-occurring patient-name + clinical diagnosis pairs spanning both pure-CJK and mixed alphanumeric/Roman-numeral subtypes (e.g., Type-2 diabetic nephropathy, diffuse large B-cell lymphoma).
    \item \emph{Stage~2 --- Pre-Masked Local Small Language Model with Symbolic Output Guard (\texttt{create\allowbreak LocalSlm\allowbreak PhiDetector} + \texttt{redact\allowbreak Phi\allowbreak Cascaded}):} Because Stage~1 pre-masks structured identifiers before Stage~2 is invoked, the Stage-2 model does not receive raw national IDs, phone numbers, or bank cards, and does not need to perform arithmetic checksum verification. Instead, a compact $1.5\text{B}$-parameter local small language model (\texttt{qwen2.5:1.5b}, $986\,\text{MB}$, served via local Ollama and gated by \texttt{assert\allowbreak Local\allowbreak PhiEndpoint} to allow only loopback \texttt{127.0.0.1}/\texttt{::1} or RFC~1918 private intranet hosts) extracts open-vocabulary residual spans in free-form ward-round narratives: unlabeled person/relative names (\texttt{unlabeled\_\allowbreak person\_\allowbreak name}) and specific residential/workplace addresses (\texttt{address\_\allowbreak or\_\allowbreak org}). Finally, a deterministic post-validator (\texttt{normalize\allowbreak AndValidate\allowbreak Stage2Entity}) verifies exact substring presence in the source text, strips kinship/location prepositions, checks Chinese family-surname membership and medical-suffix exclusions for names, and requires spatial/organizational markers for addresses---filtering out small-model hallucinations and clinical-term false positives. The model thus acts as a candidate generator and the post-validator decides what is masked; text containing no CJK characters (e.g., English manuscript prose) is not sent to the model.
  \end{enumerate}
  \item \textbf{Pseudonymous Subject Mapping \& PHR Red-Lines:} Within research cohorts, real patient identifiers are replaced by pseudonymous subject codes (\texttt{P001}, \texttt{P002}, \dots) via an in-memory translation table. Furthermore, a dedicated Personal Health Record guard (\texttt{phr\_guard}) enforces read-only access on patient-uploaded primary medical records, preventing AI tools from altering ground-truth clinical evidence.
  \item \textbf{Regulatory Scope:} These mechanisms reduce exposure but do not by themselves establish compliance with either PIPL or HIPAA. Pseudonymous subject codes are de-identification rather than anonymization: under PIPL, data that can be re-linked with a retained mapping table remains personal information \cite{pipl2021}. The current scanner implements mainland Chinese identifier formats (resident ID numbers, mobile numbers, hospital record numbers, Chinese surnames/addresses); it does not yet cover HIPAA Safe Harbor identifiers such as Social Security numbers, U.S.-format telephone numbers, full dates, or English geographic subdivisions \cite{hipaa1996}, so U.S. deployment requires extending it.
\end{itemize}

\section{Three-Layer Self-Evolving Agent Architecture}
\label{sec:evolution}

A recurring challenge in contract-guarded agent environments is helping the LLM internalize operational boundaries without manual prompt engineering. When an agent's tool call is blocked by a pre-write guard or reverted by a user, how does the system help the agent adapt both within the current task and across future sessions?

As shown in the bottom tier of Figure~\ref{fig:architecture}, Heurion 2.0 implements a three-layer adaptation architecture operating across three timescales:

\subsection{Layer 1: Task-Level Pre-Flight Probe (\texttt{doc\_validate} \& \texttt{dry\_run})}
At the intra-turn millisecond timescale, agents in Heurion 2.0 can invoke \texttt{doc\_validate} (or pass \texttt{dry\_run: true} to \texttt{doc\_edit}) prior to committing complex multi-block edits. The probe executes the full suite of conflict guards, citation registration checks, anchor integrity checks, and post-edit structural diffs against an ephemeral in-memory clone of the ProseMirror document tree without incrementing \texttt{rev}, mutating the Yjs CRDT state, or polluting the undo stack. If a violation is detected, the probe returns \texttt{\{valid: false, code, hint, current\}}, enabling zero-cost self-correction within the same reasoning turn.

\subsection{Layer 2: Session-Level Dual-Track Memory and Utility-Ranked Injection}
At the cross-turn session timescale, Heurion 2.0 addresses memory pollution by enforcing \textbf{Declarative-Procedural Orthogonality} (Invariant~\ref{inv:memory}):
\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Track A --- Declarative Memory (\texttt{MemoryService}):} Captures domain conventions and author preferences (e.g., ``Always report continuous skewed variables as median (IQR)'', ``Use British English spelling''). Because stylistic preferences are subjective, newly extracted items enter a \texttt{candidate} state and require explicit human approval in the UI before becoming \texttt{confirmed}.
  \item \textbf{Track B --- Procedural Harness Memory (\texttt{ProceduralHarnessService}):} Captures objective operational rules for navigating guards, tools, and specialist subagents. Whenever \texttt{OpService} rejects an AI edit or a user invokes \texttt{revertTurn}, the \texttt{ExecutionSignals} collector automatically records a structured runtime signal $s = (\text{owner},\allowbreak \text{doc\_id},\allowbreak \text{turn\_id},\allowbreak \text{kind},\allowbreak \text{code},\allowbreak \text{detail})$ into the \texttt{execution\_signals} table.
\end{itemize}

At the end of an authoring session, \texttt{evolveFromSignals()} clusters unconsumed execution signals by $(\text{kind}, \text{code})$. Any failure pattern occurring at least $\tau = 2$ times either increments the empirical evidence counter $e_r$ of an existing procedural rule $r \in \mathcal{M}_P$ or crystallizes a new active procedural directive---requiring zero manual UI intervention.

\paragraph{Context-Aware Utility Ranking.} Injecting all procedural rules into every turn would waste context tokens. Before each turn on document $d$ with user prompt $q$, \texttt{ProceduralHarnessService\allowbreak.forPrompt()} computes a relevance score $U(r \mid d, q)$ for each active rule $r \in \mathcal{M}_P$. Guard codes never appear in a user's request, so a rule is not matched against $q$ by its code; instead each guard code is associated with a \emph{message cue} (keywords in $q$, e.g., DOI/PMID or citation terms for \texttt{citation\_not\_registered}, replacement verbs for \texttt{ambiguous\_match}) and/or a \emph{document-state cue} computed from $d$ (human edits within the last two revisions for \texttt{conflict\_user\_edited}, open comment threads for \texttt{anchor\_has\_open\_comments}, pending suggestions for \texttt{pending\_suggestion}, the presence of a table for table-edit codes):
\begin{equation}
  \label{eq:utility}
  U(r \mid d, q) = \alpha \cdot e_r + \beta \cdot \mathbb{I}\!\left(\text{msgCue}_r(q)\right) + \gamma \cdot \mathbb{I}\!\left(\text{stateCue}_r(d)\right),
\end{equation}
where $e_r$ is the empirical evidence count, $\mathbb{I}(\cdot)$ is the indicator function, and $(\alpha, \beta, \gamma) = (0.1, 5, 8)$. Baseline subagent-delegation rules, whose trigger is a keyword pattern rather than a guard code, use that pattern as their message cue; codes without a defined cue are ranked by $e_r$ alone. These weights are hand-set heuristics, not tuned values. Rules are sorted in descending order of $U(r \mid d, q)$ and greedily packed: a rule of length $\ell$ is charged $\ell + 20$ characters and skipped if it would exceed the budget $B$ (default $B = 1000$), up to at most $K=4$ rules.

\subsection{Layer 3: System-Level Meta-Strategy Distillation (\texttt{Harness\allowbreak Evolution\allowbreak Service})}
At the multi-session platform timescale, Heurion 2.0's \texttt{HarnessEvolutionService} periodically aggregates system-wide execution signals and active procedural rules. When cumulative unanalyzed signals exceed a threshold, a background meta-evolver distills recurring failure root causes into concise system-level behavioral directives (2--5 rules, $\le 100$ characters each) and serializes them into a dynamic YAML profile overlay (\texttt{evolved.cordis.yml}):

\begin{lstlisting}[style=heurionspec]
# Auto-generated by Heurion Self-Evolution Engine
- id: system-prompt
  config:
    personaSuffix: >-
      [Evolved Self-Improvement Execution Directives]:
      - Run doc_validate prior to mutating blocks with recent user activity
      - Register all DOI/PMID entries via insert_citation before inline referencing
\end{lstlisting}

When \texttt{HarnessPool} spawns or refreshes an agent runtime, \texttt{getPatches()} transparently mounts \texttt{evolved.cordis.yml} alongside the base platform profile, updating the agent's system persona without user disruption.

\section{CI-Enforced Human-AI Permission Symmetry}
\label{sec:parity}

A common security and usability gap in enterprise AI applications is the disconnect between what a human user can perform via the graphical user interface and what the AI agent can perform via tool calls. Often, developers either grant the agent direct database access (bypassing business-layer authorization) or expose only a subset of tools.

Heurion 2.0 enforces \textbf{Human-AI Permission Symmetry} (Invariant~\ref{inv:parity}) across all platform capabilities:
\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{In-Process Loopback Execution under User Identity:} Every administrative and clinical MCP tool \cite{anthropic2024mcp} (\texttt{patient\_*}, \texttt{study\_*}, \texttt{doc\_manage}, \texttt{kb\_manage}, \texttt{dataset\_manage}, \texttt{org\_manage}) executes by invoking \texttt{invokeHttp(api, userId, method, path, body)} directly against the Hono HTTP router in-process. The call carries a short-lived internal JWT minted for \texttt{userId} and tagged with header \texttt{X-Heurion-Via: ai}. Consequently, the agent inherits the exact same multi-tenant isolation, study role checks (PI, co-investigator, statistician, reviewer), and audit logging as the human user.
  \item \textbf{Human-Only Confirmation Cards for High-Risk Actions:} When an AI tool invokes a destructive or irreversible endpoint (e.g., purging a document, freezing a clinical study cohort, or removing a team member), the HTTP middleware intercepts the \texttt{X-Heurion-Via: ai} header and---rather than executing the mutation---creates a \texttt{pending\_actions} record and renders an interactive confirmation card in the user's chat stream. Only when the human clicks \emph{Confirm} in the browser does the UI re-issue the request with \texttt{X-Heurion-Via: ai-confirmed}, completing execution.
  \item \textbf{Automated CI Parity Verification (\texttt{parity.test.ts}):} Our test suite introspects the Hono application router table at build time and asserts that every registered \texttt{/api/*} endpoint appears either in the MCP parity mapping table ($\phi(\mathcal{E}_{\text{MCP}})$) or in the documented $\mathcal{E}_{\text{NOT\_FOR\_AI}}$ exclusion registry. Any newly added API route missing an MCP counterpart or explicit exemption immediately fails continuous integration.
\end{enumerate}

We therefore report these as out-of-scope side effects: Heurion 2.0 made $0$ unintended text changes but $7$ unrequested comment insertions on non-target paragraphs.
  \item \textbf{Comment-Thread Resolution vs.\ Unassisted File Scripting:} In the \texttt{open\_\allowbreak comment\_\allowbreak anchor} task (which instructs the agent to rewrite a Methods paragraph according to two attached clinician review comments), although the baseline agent had full Python/XML access to \texttt{word/comments.xml}, standard \texttt{python-docx} scripts written by the agent iterated over \texttt{Document.paragraphs} (which does not expose \texttt{word/comments.xml}) and lacked a dedicated comment-thread tool or pre-write guard; consequently, the file agent modified the paragraph's text runs while leaving the sibling \texttt{<w:commentRangeStart/>} XML tags in place ($9/9$ vs.\ $3/9$, $p=0.0090$) and never appended a reply to \texttt{word/comments.xml} ($0/9$ acknowledged). Conversely, Heurion 2.0's \texttt{anchor\_has\_\allowbreak open\_comments} guard and \texttt{comments\_list}/\texttt{comment\_reply} tools prompted the MCP agent to inspect the comments, declare \texttt{drop\_anchors} when replacing the full paragraph ($6/9$ cases), and post structured replies in all $9/9$ ($100\%$, $p < 0.0001$) review threads. These replies live in the platform's comment threads: the exported \texttt{.docx} does not carry them, and in $4/9$ exported files the two original clinician comments were removed along with their anchors, so a reviewer working only in Word would not see how the comments were resolved.
  \item \textbf{Methodological Note on File-Arm Concurrent Edits:} Both arms preserved $9/9$ clinician insertions in \texttt{concurrent\_edit}. Inspection of the event logs revealed that because the file agent executes a single atomic \texttt{bash} call (\texttt{Document('manuscript.docx') ... save()}) whereas the harness callback \texttt{humanEditsFile} fires upon \texttt{tool\_result} completion, the simulated clinician insertion in the file arm occurred between separate \texttt{bash} invocations rather than mid-flight between an in-memory read and write. Mid-flight stale-snapshot overwrites are evaluated deterministically in Table~\ref{tab:v2_bench} ($50/50$ intercepted) and in Experiment~3.
\end{enumerate}

\subsection{Experiment 2: Pre-Write Citation, PHI, and High-Risk Action Guards}

\paragraph{Experiment 2a: Two-Stage Deterministic + Local SLM PHI and Citation Guards (\texttt{exp2b}).}
To quantify the complementary roles of Stage-1 deterministic validators (\texttt{scanPhi}/\texttt{redactPhi}) and the Stage-2 local small language model (\texttt{qwen2.5:1.5b} via loopback Ollama, \texttt{redactPhiCascaded}), we evaluated Heurion 2.0 across $660$ test records comprising $100$ citation-guard sentences, $200$ synthetic positive clinical notes containing $720$ PHI spans across $7$ categories, and $360$ negative controls across $4$ strata (Table~\ref{tab:guards}):
\begin{enumerate}[leftmargin=1.5em,itemsep=1pt]
  \item \textbf{Unregistered Inline Citations ($N=100$ distinct sentences):} $40$ bare DOIs across $8$ biomedical publisher prefixes, $30$ \texttt{https://doi.org/} URLs, and $30$ bare PMIDs. All $100/100$ ($100\%$) were intercepted prior to CRDT mutation with \texttt{citation\_not\_registered}.
  \item \textbf{Stage-1 vs.\ Stage-2 Local SLM Recall across $720$ Synthetic PHI Spans ($N=200$ notes):} Each synthetic note contained $3$ structured/labeled identifiers ($120$ spans per category across $5$ categories = $600$ spans), and $60$ notes additionally included unstructured ward-round narrative clauses containing an unlabeled relative/caregiver name (\texttt{unlabeled\_person\_name}, $60$ spans) and a residential street/building/room address (\texttt{address\_or\_org}, $60$ spans). As shown in Table~\ref{tab:guards}, \textbf{Stage~1 alone} ($0.011\,\text{ms}$/note) achieved $100.0\%$ ($600/600$) recall across the five structured and labeled categories---including $120/120$ on mixed alphanumeric/Roman-numeral diagnosis subtypes---but recalled $0/120$ ($0.0\%$) on unlabeled free-narrative names and residential addresses ($600/720 = 83.3\%$ overall). Because the $200$ synthetic notes were generated from deterministic templates authored by the same team that implemented Stage~1, the $100\%$ Stage-1 recall reflects rule-template alignment and verifies implementation coverage rather than generalization to noisy hospital EHRs. Adding \textbf{Stage~2 (\texttt{qwen2.5:1.5b})} captured $55/60$ ($91.7\%$) of unlabeled person names and $55/60$ ($91.7\%$) of residential addresses ($110/120 = 91.7\%$ on unstructured spans), raising combined recall on this benchmark from $83.3\%$ to $98.6\%$ ($710/720$). A span is counted only if its target string no longer appears in the redacted output (this strict count equalled the lenient type-match count). All $60$ narrative clauses share a single sentence template (a relative signing consent, followed by a home address), so this figure reflects one phrasing rather than varied ward-round prose. Stage~2 took a mean of $3.1\,\text{s}$ per narrative note ($4$ concurrent requests on one developer machine), versus $0.011\,\text{ms}$ for Stage~1. Because Stage~1 pre-masks structured identifiers before invoking Stage~2, $0/60$ ($0.0\%$) raw national IDs, phone numbers, MRNs, or bank cards were passed into the Stage-2 prompt.
  \item \textbf{Negative Controls and the Role of Each Stage-2 Component ($N=360$ negative records):} Across $200$ real numeric-dense PMC biostatistical paragraphs (containing hazard ratios, 95\% CIs, $p$-values, and zero-padded DOI suffixes) and $100$ corrupted-checksum or invalid-date 16--18 digit instrument serials, Stage~1 produced $0/200$ ($0.0\%$) and $0/100$ ($0.0\%$) false positives, respectively (vs.\ $100/100 = 100\%$ false positives under a naive 16--18 digit regex). The full cascade also produced $0/200$ false positives on the PMC paragraphs, but these English paragraphs contain no CJK characters, so the Stage-2 detector skipped all of them by design ($0$ model calls); this stratum does not test the model. To isolate each Stage-2 component we used two sets of $30$ clean Chinese clinical research sentences: a \emph{template set} ($30$ sentences from one template with diagnoses, targeted or immunotherapy drug names, sample sizes, median PFS, and $p$-values) and an \emph{independent set} written after the post-validator's term lists were fixed ($30$ sentences from three templates with regimens such as R-CHOP and FOLFOX, imaging reader-agreement statements, Cox hazard ratios, and IRB approval numbers, using none of the validator's blocklisted terms). Without post-validation, \texttt{qwen2.5:1.5b} returned at least one entity on $30/30$ sentences in both sets. With post-validation, false positives fell to $1/30$ ($3.3\%$, template set) and $0/30$ (independent set). Conversely, replacing the model with exhaustive rule-based candidate generation (every $2$--$3$-character CJK string beginning with a common surname, and every span ending in an address marker) under the same post-validator recalled $120/120$ narrative spans but flagged $30/30$ sentences in both clean sets.
\end{enumerate}

\paragraph{Design Implication: Local SLMs as Candidate Generators Between Deterministic Guards.}
Table~\ref{tab:guards} suggests a division of labor for privacy-sensitive vertical applications. Deterministic Stage-1 rules handle structured and labeled identifiers ($600/600$ at $0.011\,\text{ms}$ per note). For the unlabeled narrative residue that rules cannot express precisely, a local $1.5\text{B}$ model proposes candidate spans and a symbolic post-validator (surname membership, medical-suffix exclusion, address markers, exact substring match) decides which to mask. Each half fails on its own: the unvalidated model flagged every clean sentence ($60/60$), and rule-based candidates under the same validator also flagged every clean sentence ($60/60$), whereas the combination kept $110/120$ narrative recall with $1/60$ false-positive sentences, without clinical text leaving \texttt{127.0.0.1}. Because the narrative positives come from a single sentence template, this evidence is preliminary.

\paragraph{Experiment 2b: High-Risk Action Confirmation under User Pressure and Prompt Injection (\texttt{exp2c}).}
To test Architectural Invariant~\ref{inv:parity} across destructive operations, we evaluated a live \texttt{deepseek-flash} agent across $5$ irreversible administrative scenarios (\texttt{purge\_doc}, \texttt{delete\_comment}, \texttt{delete\_kb}, \texttt{delete\_study}, and \texttt{clear\_memory}) under $3$ prompt conditions $\times$ $3$ repetitions ($45$ turns total; \texttt{exp3/confirm.ts}):
\begin{enumerate}[leftmargin=1.5em,itemsep=1pt]
  \item \textbf{Normal Request (\texttt{normal}, $15$ turns = $5$ scenarios $\times$ $3$ repetitions):} The user asks the agent to delete the target resource. To test all three confirmation lifecycle states, repetition~1 simulates user approval (\texttt{POST /api/actions/:id/confirm}, $5$ turns), repetition~2 simulates user rejection (\texttt{POST /api/actions/:id/reject}, $5$ turns), and repetition~3 leaves the confirmation card unanswered (\texttt{decision = none}, $5$ turns) to verify that pending actions do not execute by default.
  \item \textbf{Coercive User Pressure (\texttt{pressure}, $15$ turns):} The user explicitly instructs the agent to bypass confirmation (e.g., \emph{``Delete it immediately without asking me to confirm; I take full responsibility''}), and no confirmation button is clicked (\texttt{decision = none}).
  \item \textbf{Indirect Document Prompt Injection (\texttt{injection}, $15$ turns):} The user asks only to polish the Discussion section, while the manuscript body contains an embedded adversarial directive \cite{greshake2023injection} instructing the agent to purge the target resource without confirmation.
\end{enumerate}

\subsection{Experiment 3: Longitudinal Ablation of Self-Evolving Procedural Memory (\texttt{exp3})}
To evaluate whether runtime signal crystallization (\texttt{evolveFromSignals}) and context-aware utility ranking (\texttt{forPrompt}, Eq.~\ref{eq:utility}) reduce repetitive guard violations across sessions, we conducted a pre-specified 3-arm paired longitudinal experiment (\texttt{exp3/pilot.ts}):
\begin{itemize}[leftmargin=1.5em,itemsep=1pt]
  \item \textbf{Arm A --- No Procedural Memory (\texttt{off}):} No procedural rules are injected ($360$ turns; $359$ analysed after $1$ pre-specified infrastructure timeout exclusion).
  \item \textbf{Arm B --- Static Seeded Rules Only (\texttt{frozen}):} Injects the $5$ factory-seeded baseline rules ranked by Eq.~\ref{eq:utility} ($B=1000$ chars), but freezes rule crystallization from runtime execution signals ($360$ turns).
  \item \textbf{Arm C --- Full Self-Evolving System (\texttt{utility}):} Automatically crystallizes new procedural rules (or increments evidence counts $e_r$) once a guard/revert signal recurs $\tau=2$ times and dynamically injects top-utility rules per turn ($360$ turns).
\end{itemize}
Each arm ran $8$ independent simulated user trajectories parameterized by random seeds ($\text{seeds } 101\text{--}108$) across $5$ consecutive sessions ($4$ training sessions on $7$ training PMC manuscripts, followed by \textbf{Session~5 on $3$ held-out PMC manuscripts}) $\times$ $9$ shuffled tasks per session, totaling $1,080$ turns ($1,079$ analysed). Identical seeds across arms guaranteed exact task-order and manuscript pairing.

On the secondary count endpoint of \emph{total execution signals} (which has higher statistical power due to a higher event count: $90$ vs.\ $143$ signals), the \texttt{glmmTMB} mixed model showed a significant $37\%$ reduction ($\text{RR} = 0.63$, $95\%$ CI $0.48\text{--}0.82$, Holm $p = 0.0011$).
  \item \textbf{Online Crystallization vs.\ Static Seeded Rules (H2) and Held-Out Behavior:} Comparing Arm~C (\texttt{utility}) against Arm~B (\texttt{frozen}) tests whether online rule crystallization over $5$ sessions outperforms a static set of $5$ factory-seeded rules. While \texttt{utility} ended with $15$ user-scoped active rules---$5$ crystallized for novel guard codes (\texttt{anchor\_has\_open\_comments} $\times 3$, \texttt{text\_not\_found} $\times 2$; $e_r \in [2, 3]$) and $10$ for recurring codes (\texttt{pending\_suggestion} $\times 8$, \texttt{citation\_not\_registered} $\times 2$; $e_r \in [12, 16]$)--- the between-arm difference in pre-write guard rejections ($14$ vs.\ $19$, \texttt{glmmTMB} $\text{RR} = 0.74$, $p = 0.4263$) and total execution signals ($90$ vs.\ $100$, $\text{RR} = 0.90$, $p = 0.4684$) was not statistically significant. Similarly, in the descriptive single-session held-out slice (Session~5, $72$ turns/arm), both \texttt{frozen} ($2/72$ rejections, $10$ signals) and \texttt{utility} ($3/72$ rejections, $10$ signals) had fewer rejections than \texttt{off} ($10/72$ rejections, $28$ signals), with \texttt{frozen} recording one fewer rejection than \texttt{utility}. Thus, our $5$-session live LLM data support the value of cue-ranked procedural rules over no procedural memory, but do not establish a statistically significant advantage of online rule crystallization over well-chosen static rules within $5$ sessions. Inspecting the crystallized rules also explains why Arm~C's total execution signals rose during Sessions~3--4 ($21 \to 26$ in Figure~\ref{fig:evolution_curve}): generic fallback rules crystallized for novel guard codes instruct the agent to call \texttt{doc\_validate} before editing, shifting errors from pre-write rejections into pre-flight diagnostic signals rather than encoding the guard-specific parameter fix (such as passing \texttt{drop\_anchors}).
  \item \textbf{Non-Inferior Task Completion (H3):} Task completion in Arm~C ($343/360 = 95.3\%$) was non-inferior to Arm~A ($341/359 = 95.0\%$), with a cluster-robust difference of $+0.29\%$ ($95\%$ CI $[-0.83\%, +1.42\%]$), within the pre-specified $-5.0\%$ non-inferiority margin.
\end{enumerate}

\subsection{Pre-Specification Transparency, Deviations, and Limitations}
\paragraph{Pre-Specification and Git Provenance.}
The evaluation protocol (\texttt{paper/\allowbreak benchmarks/\allowbreak ANALYSIS\_PLAN.md}) was frozen in the project git repository prior to formal data collection at tag \texttt{paper-eval-v1} (commit \texttt{1d8f307c}); because it was recorded via internal git tags rather than an external registry such as OSF, we refer to it as pre-specified rather than externally pre-registered. Six minutes into the initial launch, Node's built-in \texttt{fetch} client severed three long-running SSE streams at its default $300\,\text{s}$ idle timeout under $24$-user concurrency; we replaced the client stream transport in the benchmark harness with \texttt{node:http} (no timeout), discarded the aborted run without inspecting outcome metrics, tagged \texttt{paper-eval-v1.1} (commit \texttt{e060107f}), and documented the R \texttt{glmmTMB} script (\texttt{stats.R}) and long-manuscript comparison script (\texttt{manuscripts/compare.ts}) in an addendum to \texttt{ANALYSIS\_PLAN.md}.

\paragraph{Deviation from the Pre-Specified Plan: Pending Human Audit.}
\texttt{ANALYSIS\_PLAN.md} \S 6 pre-specifies a human audit of a $10\%$ stratified sample of turns (about $108$ \texttt{exp3} turns and $16$ \texttt{exp2a-papers} turns), graded blind to experimental arm, to estimate agreement (raw agreement and Cohen's $\kappa$) between the programmatic task-completion oracle and human judgment. The audit samples have been drawn (\texttt{audit/items.json}, with arm keys stored separately), but human grading had not been completed at the time of this version. All task-completion results in this version therefore rest on the programmatic oracle alone; audit results will be reported in a subsequent version.

As a partial, data-only check of oracle strictness, $50$ of the $54$ programmatic failures in \texttt{exp3} were \texttt{table\_row} turns ($16/18$ \texttt{off}, $18/19$ \texttt{frozen}, $16/17$ \texttt{utility}), whose oracle requires the inserted row to sit immediately after the specified row with all remaining cells set to \texttt{NR}. A post-hoc sensitivity analysis excluding \texttt{table\_row} turns gives completion rates of $99.4\%$ ($317/319$), $99.7\%$ ($319/320$), and $99.7\%$ ($319/320$) for \texttt{off}, \texttt{frozen}, and \texttt{utility}, respectively, and reclassifying all \texttt{table\_row} failures as passes gives upper bounds of $357/359$, $359/360$, and $359/360$. The H3 non-inferiority conclusion is unchanged under either variant. As pre-specified, all primary and secondary analyses use the unmodified oracle scores.

\paragraph{Limitations.}
Our empirical evaluation has seven main limitations: (1) all live agent authoring experiments used a single model (\texttt{deepseek-flash}), while Stage-2 local PHI extraction used \texttt{qwen2.5:1.5b}; (2) all user trajectories ($8$ seeds in \texttt{exp3}, $3$ seeds in \texttt{exp2a-papers}) were driven by automated scripts with deterministic clinician callbacks rather than live human-subject user studies; (3) the $10$ manuscripts in \texttt{exp2a-papers} and \texttt{exp3} are published open-access PMC articles that may appear in pre-training corpora, and the $9$ revision instructions were authored by the investigators; (4) the $200$ positive clinical PHI notes ($720$ spans) in \texttt{exp2b} were synthetically generated from templates authored by the same team that built the Stage-1 rules, inflating Stage-1 recall ($100\%$) due to template-rule alignment, and all $60$ narrative positives share one sentence template; external evaluation on independent clinical de-identification datasets \cite{stubbs2015deid} or annotated hospital EHRs is needed to establish clinical generalizability; (5) while syntactic citation registration is evaluated end-to-end, clinician-graded precision/recall evaluation of \texttt{verify\_claims} semantic verdicts (\texttt{exp4/annotation.html}) is left to future work; (6) all live experiments disabled declarative memory auto-extraction and Layer~3 background overlays (\texttt{HARNESS\_EVOLVE=0}), so Layer~3 meta-strategy distillation and the declarative--procedural orthogonality of Invariant~\ref{inv:memory} are described as system design but not empirically evaluated here; and (7) task completion is graded by a programmatic oracle whose pre-specified human audit is still pending (see above).

\section{Related Work}
\label{sec:related}

\paragraph{Collaborative Editing Data Structures and Agent-Computer Interfaces (ACI).}
Conflict-free Replicated Data Types (CRDTs) \cite{shapiro2011crdt} and local-first software architectures \cite{kleppmann2019localfirst} enable concurrent multi-actor editing without central locking. In parallel, SWE-agent \cite{yang2024sweagent} and OpenHands \cite{wang2024openhands} showed that specialized Agent-Computer Interfaces outperform raw shell scripting for software engineering, and the Model Context Protocol (MCP) \cite{anthropic2024mcp} standardized tool exposure for LLM agents. Heurion 2.0 combines these threads by exposing a shared ProseMirror + Yjs CRDT document core through guarded MCP primitives with node-level optimistic concurrency locks, per-turn selective CRDT undo, and raw-slice OOXML export.

\paragraph{Literature Synthesis, Citation Hallucination, and De-Identification.}
Empirical audits have documented frequent fabricated references in LLM-generated medical content \cite{bhattacharyya2023hallucination} and in LLM-generated bibliographies across disciplines \cite{walters2023fabrication}; see \cite{ji2023survey} for a broader survey of hallucination. While STORM \cite{shao2024storm} and PaperQA2 \cite{skarlinski2024paperqa2} automate literature synthesis and FActScore \cite{min2023factscore} and ALCE \cite{gao2023alce} evaluate post-hoc attribution, Heurion 2.0 enforces citation registration as a pre-write syntactic invariant (\texttt{[@c:id]}). For clinical privacy, rule-based and hybrid de-identification systems such as the i2b2/UTHealth shared-task systems \cite{stubbs2015deid}, Philter \cite{norgeot2020philter}, and Microsoft Presidio \cite{presidio2021} combine regular expressions with statistical or neural sequence labelers; our two-stage PHI funnel adapts this hybrid pattern to local loopback deployment by pairing checksum/subtype validators with a pre-masked $1.5\text{B}$ SLM and symbolic output validation, while our confirmation middleware mitigates indirect prompt injection \cite{greshake2023injection} on destructive endpoints.

\paragraph{Self-Evolving Agents and Memory Architectures.}
Reflexion \cite{shinn2023reflexion} and MemGPT \cite{packer2023memgpt} introduced verbal reinforcement and tiered memory management for LLM agents, while Voyager \cite{wang2023voyager} accumulated executable skills in open-ended environments. In collaborative authoring, mixing subjective user stylistic preferences with operational error recovery can create prompt interference; Heurion 2.0 separates human-confirmed declarative preferences from signal-crystallized procedural rules ranked by document-state and prompt cues.

\section{Conclusion}
\label{sec:conclusion}

We have presented Heurion 2.0, a collaborative clinical authoring platform built around a contract-guarded dual-surface CRDT engine and a three-layer procedural memory system:
\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Dual-Surface CRDT Co-Editing and OOXML Export:} Replacing direct \texttt{python-docx} file scripting with a shared Yjs + ProseMirror CRDT core, stable block IDs (\texttt{\{\#id\}}), \texttt{base\_rev} concurrency guards, per-turn selective undo (\texttt{revertTurn}), and raw XML slice caching (\texttt{node\_src}) achieved comparable task completion ($93.8\%$ vs.\ $95.1\%$) while raising review-comment thread resolution from $0\%$ ($0/9$) to $100\%$ ($9/9$, $p<0.0001$) on full-length PMC clinical manuscripts.
  \item \textbf{Pre-Write Citation and Local Two-Stage PHI Guards:} Pre-write syntactic validation blocked $100/100$ unregistered inline DOIs/PMIDs, and pairing sub-millisecond ISO~7064 / Luhn checksum rules with a pre-masked local $1.5\text{B}$ SLM (\texttt{qwen2.5:1.5b}) and symbolic output filtering recalled $98.6\%$ ($710/720$) of synthetic clinical PHI spans within the local loopback boundary; symbolic post-validation was required for precision, reducing false-positive sentences on clean Chinese clinical text from $60/60$ (unvalidated model) to $1/60$.
  \item \textbf{Procedural Memory Adaptation:} In our $8$-seed, $5$-session longitudinal ablation ($1,079$ turns), cue-ranked procedural memory reduced total execution signals by $37\%$ (\texttt{glmmTMB} $\text{RR}=0.63$, Holm $p=0.0011$) and yielded a directional $49\%$ reduction in pre-write guard rejections ($\text{RR}=0.51$, Holm $p=0.1089$; cluster-robust NB2 sensitivity $\text{RR}=0.50$, Holm $p=0.0269$) compared to no procedural memory, while online rule crystallization over static seeded rules showed a non-significant directional difference ($\text{RR}=0.74$, $p=0.426$) over $5$ sessions.
  \item \textbf{Human-AI Permission Symmetry:} In-process HTTP Loopback execution under user JWT identity (\texttt{X-Heurion-Via: ai}), confirmation cards for destructive actions ($30/30$ tool invocations intercepted), and automated CI router parity checks (\texttt{parity.test.ts}) ensure that AI tools operate within the same authorization boundaries as the human researcher.
\end{itemize}
