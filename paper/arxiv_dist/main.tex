% ABSTRACT
% ============================================================================
\begin{abstract}
Autonomous large language model (LLM) agents have achieved strong results in software engineering through free-form shell execution and direct file editing. However, applying this ``script-and-audit'' workflow to clinical and scientific research causes serious failures: broken formatting in Office Open XML (\texttt{.docx} and \texttt{.pptx}) manuscripts, silent overwriting of concurrent human edits, fabricated literature identifiers (DOIs and PMIDs) or unverified statistical claims, accidental exposure of Protected Health Information (PHI), and repeated guard failures across sessions.

We present \textbf{Heurion 2.0}, a collaborative clinical research and scientific authoring platform built around two core ideas: a \emph{Contract-Guarded Dual-Surface Document Engine} and a \emph{Three-Layer Self-Evolving Memory System}. First, instead of letting agents edit raw files on disk with ad-hoc scripts, Heurion 2.0 keeps a single Conflict-free Replicated Data Type (CRDT) document state (ProseMirror + Yjs) with stable block IDs (\texttt{\{\#id\}}). From this shared state, it projects a rich-text or slide editor for human researchers and a compact Annotated Markdown view with guarded editing tools for AI agents. This design enables per-turn selective undo of AI edits without disturbing human changes in the same paragraph, as well as 100\% byte-identical OOXML export for untouched blocks. Second, to prevent hallucinated references, pre-write guards block raw inline DOIs and PMIDs while a multi-agent verification pipeline checks manuscript claims against PubMed abstracts and PubMed Central (PMC) full texts. Third, a clinical data pipeline enforces deterministic PHI redaction, pseudonymous subject IDs (\texttt{P001}), read-only patient health records, and strict permission parity between the web UI and AI tools. Finally, a three-layer self-evolving memory system combines side-effect-free pre-flight validation, a dual-track learning engine that acquires domain conventions through exemplar corruption-and-reconstruction (Track~A) and operational rules from verifier feedback without hand-written templates (Track~B), and background profile distillation. In empirical benchmarks and live \texttt{deepseek-flash} multi-session evaluations, Heurion 2.0 achieves 100\% byte identity on unmodified OOXML blocks, sub-millisecond guard validation ($0.168\,\text{ms}$) and edit commits ($0.351\,\text{ms}$), a 62.5\% overall and 75.0\% held-out reduction in guard rejections with zero hand-crafted rule templates, and cross-domain skill transfer across clinical manuscripts, biostatistical plans, and presentation decks with zero negative transfer.
\end{abstract}

\vspace{4pt}
\noindent\textbf{Keywords:} Collaborative AI Agents, CRDT Co-Editing, Clinical Research Informatics, Citation Verification, Self-Evolving Memory, Skill Training

% 1. INTRODUCTION

\section{Introduction}
\label{sec:intro}

Clinical and biomedical research workflows require strict accuracy, traceability, and privacy compliance. A typical clinical study spans longitudinal patient record curation, cohort screening, biostatistical analysis (such as Baseline Table~1 summaries, Kaplan--Meier survival curves, Cox regression, and CONSORT flowcharts), and collaborative authoring of peer-reviewed manuscripts (\texttt{.docx}) and presentation decks (\texttt{.pptx}) \cite{schulz2010consort,vandenbroucke2007strobe}. While recent agentic systems excel at code generation \cite{yang2024sweagent,wang2024openhands} and open-domain literature review \cite{shao2024storm,skarlinski2024paperqa2}, deploying autonomous agents into day-to-day clinical research exposes four practical bottlenecks:

\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{The Free-Form File Scripting Trap:} First-generation document agents treat \texttt{.docx} and \texttt{.pptx} files as opaque disk archives, generating Python scripts (e.g., \texttt{python-docx}) to rewrite them and running post-hoc quality checks afterward. In practice, script-based rewrites strip publisher XML attributes, lose paragraph IDs (\texttt{w14:paraId}) during LibreOffice layout passes, introduce subtle punctuation drift during full-paragraph replacements, and make it impossible to undo an AI turn once a human co-author edits the same section.
  \item \textbf{Fabricated Citations and Unverified Clinical Claims:} LLMs frequently invent plausible-looking DOIs, PMIDs, hazard ratios ($HR$), and $p$-values \cite{ji2023survey,walters2023fabrication}. Prompting alone cannot guarantee that every inline citation resolves to a real publication or that reported numbers match the cited paper.
  \item \textbf{Patient Privacy (PHI) Risks and Permission Gaps:} Clinical investigators work with raw medical records containing Protected Health Information (patient names, national ID numbers, admission codes, and phone numbers). Sending unredacted text to external LLMs violates healthcare privacy regulations \cite{hipaa1996}. At the same time, giving agents direct database or shell access bypasses application-level access controls.
  \item \textbf{Cross-Session Amnesia and Memory Interference:} When an agent triggers a guard error (such as editing a paragraph that carries an open review comment or merging non-adjacent blocks) or when a clinician reverts an AI turn, stateless agents repeat the same mistake in future sessions. Dumping all past observations into a single flat memory list mixes subjective writing style preferences with hard tool constraints, filling the prompt budget with irrelevant rules \cite{shinn2023reflexion,packer2023memgpt}.
\end{enumerate}

\subsection{Lessons from First-Generation Post-Hoc Auditing (Heurion v1)}
Before building Heurion 2.0, we deployed a first-generation system (\emph{Heurion v1 / S-Series}) where an agent ran Python scripts in a workspace shell to unpack, modify, and repackage \texttt{.docx} files while a post-turn supervisor checked text survival rates, paragraph drift, and DOI validity. Real-world use showed that \emph{post-hoc auditing happens too late}: by the time an audit script catches a broken XML run or a hallucinated citation, the file on disk is already corrupted, forcing full-file rollbacks that wipe out concurrent browser edits.

\subsection{The Heurion 2.0 Architecture and Contributions}
Heurion 2.0 replaces post-hoc file scripting with \emph{pre-write structural guards over a shared CRDT document core}, paired with a \emph{cross-domain self-evolving memory system}. Our main contributions are:

\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Contract-Guarded Dual-Surface CRDT Engine (Section~\ref{sec:dualsurface}):} We build a unified ProseMirror + Yjs document core with persistent block IDs (\texttt{\{\#id\}}), block-level optimistic concurrency checks (\texttt{base\_rev}), minimal-diff XML updates that preserve inline formatting and comment anchors, per-turn selective CRDT undo, and 100\% byte-preserving OOXML export for unmodified blocks.
  \item \textbf{Zero-Hallucination Evidence \& Clinical Privacy Pipeline (Section~\ref{sec:evidence}):} We block raw inline DOIs and PMIDs before any write occurs, requiring registration through Crossref, PubMed, and OpenAlex into atomic citation nodes (\texttt{[@c:id]}). A multi-agent verifier checks sentence-level claims against PubMed abstracts and PMC full texts, while a multi-tenant clinical sandbox enforces checksum-verified PHI redaction, pseudonymous subject IDs (\texttt{P001}), and reproducible biostatistical execution.
  \item \textbf{Cross-Domain Three-Layer Self-Evolving Memory (Section~\ref{sec:evolution}):} We design a three-timescale adaptation loop: (Layer~1) side-effect-free pre-flight validation probes, (Layer~2) a domain-agnostic dual-track memory engine that combines self-supervised corruption-and-reconstruction skill training (Track~A) with zero-template procedural rule synthesis and backward credit assignment (Track~B), and (Layer~3) background distillation into dynamic agent profile overlays.
  \item \textbf{Verified Human-AI Permission Symmetry (Section~\ref{sec:parity}):} We enforce and automatically test in CI that every REST API endpoint either maps 1-to-1 to an in-process Model Context Protocol (MCP) tool running under the user's exact identity and role permissions, or is explicitly listed in an audited human-only exclusion registry, with destructive actions gated by interactive confirmation cards.
\end{itemize}

Three practical design principles guide the system:

\paragraph{Principle 1: Pre-Write Structural Safety.}
Every batch of AI edit operations is validated against the live CRDT tree \emph{before} any state change occurs. A whole-block replacement is allowed only if no human user has edited that block since the revision (\texttt{base\_rev}) the agent read. Likewise, any edit that introduces an unregistered citation identifier, breaks a table grid, or deletes an active review comment anchor without acknowledgment is rejected atomically. When a batch is rejected, the document remains untouched and the guard returns a structured error code, a diagnostic hint, and the latest block text so the agent can recover immediately.

\paragraph{Principle 2: Human-AI Permission Symmetry.}
An AI agent should neither hold superuser privileges over the database nor be restricted to a toy subset of actions. In Heurion 2.0, every REST API route exposed to the browser UI is either paired 1-to-1 with an MCP tool that executes in-process under the logged-in user's exact session token and tenant permissions, or is explicitly listed in an audited human-only exclusion list (such as password changes or final confirmation endpoints). High-risk operations triggered by an agent pause and render a confirmation card in the user's chat stream before executing.

\paragraph{Principle 3: Separating Domain Style Preferences from Operational Rules.}
Mixing subjective writing preferences (e.g., ``use passive voice in Methods'') with objective tool-use rules (e.g., ``move non-adjacent blocks together before merging'') causes severe prompt interference. Heurion 2.0 keeps these two tracks separate:
\begin{itemize}[leftmargin=1.5em,itemsep=1pt]
  \item \textbf{Declarative Memory (Track~A):} Stores domain conventions, writing styles, and analytical preferences. New declarative skills are proposed as candidates---either from user edits or from self-supervised exemplar training---and require human approval (or explicit activation) before taking effect.
  \item \textbf{Procedural Harness Memory (Track~B):} Stores objective operational rules for passing pre-write guards and tool verifiers. Procedural rules evolve automatically from deterministic runtime failures and intra-turn recovery trajectories without requiring manual curation in the UI.
\end{itemize}

\section{Dual-Surface Co-Editing and Byte-Preserving Document Engine}
\label{sec:dualsurface}

A key lesson from first-generation document agents is that Office Open XML (\texttt{.docx} and \texttt{.pptx}) files are delivery archives rather than collaborative editing data structures. When an agent rewrites a \texttt{.docx} file on disk while a human views the manuscript in a browser, the two sides immediately diverge.

\subsection{Shared CRDT Core with Lifecycle-Stable Block Addressing}
In Heurion 2.0, every manuscript and slide deck lives in a server-authoritative Yjs CRDT document (\texttt{Y.Doc}) backed by SQLite snapshots and an append-only revision log (\texttt{doc\_commits}). Every block node (heading, paragraph, list item, table, figure, or slide box) carries a short, persistent ID (\texttt{\{\#id\}}). When a human splits a paragraph or pastes content in the browser, the server automatically detects duplicate or missing IDs and assigns fresh unique IDs inside a system CRDT transaction, keeping block addressing consistent across the document's lifetime.

From this single CRDT core, Heurion 2.0 projects two synchronized views:
\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Human Surface:} A collaborative ProseMirror rich-text editor for manuscripts and an interactive 16:9 slide canvas for presentation decks, synchronized in real time over WebSockets.
  \item \textbf{Agent Surface:} A compact \emph{Annotated Markdown} view generated on demand via \texttt{doc\_read} and \texttt{slide\_read}. Each block ends with its stable address \texttt{\{\#id\}}, inline citations appear as atomic tokens \texttt{[@c:cite\_id]}, figures as \texttt{![alt](asset:id)}, and open inline review comments as \texttt{\{\#c:comment\_id\}}.
\end{enumerate}

\subsection{Block-Level Conflict Guards and Minimal-Diff Updates}
To prevent an AI turn from overwriting concurrent human edits, every \texttt{doc\_edit} call includes the \texttt{base\_rev} revision number read by the agent. The server checks the \texttt{node\_changes} log for any blocks edited by a human since \texttt{base\_rev}:
\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Whole-Block Edits (\texttt{replace\_block}, \texttt{delete}):} If a human has modified the target block since \texttt{base\_rev}, the edit is rejected with \texttt{conflict\_user\_edited} and returns the human's latest text. Blocks with unresolved track-changes suggestions are similarly protected by \texttt{pending\_suggestion}.
  \item \textbf{Surgical Phrase Replacement (\texttt{replace\_text}):} For targeted phrase edits inside a paragraph, the literal \texttt{find} string serves as a natural concurrency check: if the human edited a different sentence in the same paragraph, \texttt{find} still matches uniquely and succeeds; if the human changed the target phrase itself, \texttt{find} fails cleanly with \texttt{text\_not\_found}.
  \item \textbf{Mark-Preserving Minimal Diffs:} Importantly, \texttt{replace\_text} does not re-parse the whole paragraph from plain text, which would strip inline bold/italic formatting, \texttt{[@c:id]} citation nodes, and comment highlights outside the edited span. Instead, it locates the character offsets in the ProseMirror node's text stream and replaces only that slice, updating only the changed XML children between the common prefix and suffix in the underlying Yjs fragment.
\end{itemize}

\subsection{Per-Turn Selective Undo in CRDT Space}
In collaborative writing, a researcher may ask the AI to revise three paragraphs, manually edit the second paragraph, and then decide to undo the AI's turn. A standard linear undo (\texttt{Ctrl+Z} or snapshot restore) would wipe out the researcher's manual edits.

Heurion 2.0 solves this with a two-tier \emph{Per-Turn Selective Undo} (\texttt{revertTurn}):
\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{In-Memory CRDT Origin Tracking:} When an AI turn commits edits, the server tags the Yjs transaction with a turn-specific origin and attaches a scoped \texttt{Y.UndoManager}. Calling \texttt{revertTurn} undoes only the CRDT insertions and deletions made by that specific AI turn, leaving concurrent human edits---even inside the same paragraph---untouched.
  \item \textbf{Persistent Block-Level Fallback across Restarts:} Before an AI turn's first write, the server saves the pre-turn Yjs state vector in SQLite. If the server restarts before \texttt{revertTurn} is called, the engine reconstructs the pre-turn tree, reverts all AI-edited blocks that have not been touched by a human since that turn, and safely skips any block subsequently edited by the user.
\end{enumerate}

\subsection{Byte-Preserving OOXML Patch Export}
Clinical manuscripts are often imported from journal Word templates containing custom styles, headers, macros, and embedded objects. During \texttt{.docx} or \texttt{.pptx} import, Heurion 2.0 stores the original archive and caches the raw XML slice (\texttt{<w:p>} or \texttt{<w:tbl>}) of every imported block in \texttt{node\_src}. On export, any block whose ProseMirror structure is unchanged from import is written back using its exact original XML bytes; only blocks actually modified by the user or AI are re-serialized, preserving the original paragraph properties (\texttt{<w:pPr>}).

\section{Zero-Hallucination Evidence Loop and Privacy-Preserving Clinical Pipeline}
\label{sec:evidence}

\subsection{Pre-Write Citation Guard and Atomic Citation Nodes}
To stop fabricated references at the source, Heurion 2.0 blocks agents from writing raw bibliographic IDs or hand-numbered brackets in manuscript text. Before any edit is applied, the pre-write validator scans the new text for bare DOIs (\texttt{10.\textbackslash d\{4,9\}/\dots}), bare PMIDs, or unlinked bracketed reference numbers. Any match triggers \texttt{citation\_not\_registered} and aborts the write.

Instead, the agent must call \texttt{insert\_citation}, which queries Crossref, NCBI PubMed E-utilities, and OpenAlex, verifies that the publication exists, stores its canonical metadata in the document's \texttt{citations} table, and returns a registered token \texttt{[@c:cite\_id]}. In ProseMirror, \texttt{[@c:cite\_id]} is an atomic inline node that numbers itself automatically and formats the bibliography in Vancouver, AMA, APA, MLA, IEEE, or GB/T~7714 style.

\subsection{Multi-Agent Sentence-Level Claim Verification}
Registering a real paper does not prevent an LLM from misstating its findings (for example, citing a real trial but flipping the hazard ratio). Heurion 2.0 pairs specialist subagents (\texttt{literature\_researcher}, \texttt{biostatistician}, and \texttt{fact\_checker}) with an automated claim verification pipeline (\texttt{verify\_claims}):

\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Claim Extraction:} The verifier scans all document blocks, splits text into sentences, and selects (a) sentences containing \texttt{[@c:cite\_id]} citations and (b) uncited sentences containing quantitative clinical assertions (percentages, $p$-values, confidence intervals, $HR/OR/RR$, or sample sizes).
  \item \textbf{Evidence Retrieval:} For each cited paper, the verifier fetches the PubMed abstract and, when available via PubMed Central (PMC) or uploaded PDFs, the full-text sections.
  \item \textbf{Four-Way Verdict \& Inline Review Comments:} Each extracted claim receives one of four verdicts: \texttt{supported}, \texttt{contradicted}, \texttt{unsupported} (the cited paper does not mention the metric), or \texttt{uncited\_stat}. Flagged claims are attached directly to the offending sentence as inline ProseMirror review comments with excerpts from the source paper and one-click actions (apply suggested rewrite, swap citation, or mark as a \emph{Clinical Experience Exemption}).
\end{enumerate}

\subsection{Multi-Tenant PHI Redaction and Reproducible Clinical Sandbox}
To connect clinical data analysis with manuscript writing without leaking patient identities:
\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Per-Tenant Database Isolation \& Envelope Encryption:} Each organization runs on a physically separate SQLite database file with per-tenant Data Encryption Keys wrapped by a master Key Encryption Key.
  \item \textbf{Deterministic PHI Scanner:} Before any clinical note or OCR lab report enters LLM context, deterministic scanners redact 18-digit national ID numbers (validated via ISO~7064 MOD~11-2 checksum), card numbers (Luhn check), phone numbers, medical record numbers, and co-occurring patient name + sensitive diagnosis phrases.
  \item \textbf{Pseudonymous Subject IDs \& Read-Only Health Records:} Inside research cohorts, real patient identifiers are replaced with pseudonymous codes (\texttt{P001}, \texttt{P002}, \dots). In addition, a dedicated guard enforces strict read-only access on patient-uploaded Personal Health Records (PHR) so AI tools can never alter primary clinical evidence.
  \item \textbf{Sandboxed Biostatistical Execution:} Statistical computations are delegated to isolated tools and the \texttt{biostatistician} subagent, producing reproducible Baseline Table~1 summaries, Kaplan--Meier survival curves, CONSORT flowcharts, E-value sensitivity analyses, clinical prediction nomograms, and MONAI 3D medical image segmentations.
\end{itemize}

\section{Three-Layer Self-Evolving Agent Architecture}
\label{sec:evolution}

A central practical question in guarded agent environments is how an agent learns from mistakes and domain exemplars without relying on human prompt engineering or hard-coded error dictionaries. As shown in the bottom tier of Figure~\ref{fig:architecture}, Heurion 2.0 organizes self-evolution across three timescales.

\subsection{Layer 1: Task-Level Pre-Flight Probe (\texttt{doc\_validate} \& \texttt{dry\_run})}
Within a single turn, agents can call \texttt{doc\_validate} (or pass \texttt{dry\_run: true} to \texttt{doc\_edit}) before committing complex multi-block edits. The probe runs all conflict guards, citation checks, comment-anchor checks, and table validators against an in-memory clone of the ProseMirror tree without advancing the revision counter or touching the undo stack. If a check fails, the probe returns the error code, a recovery hint, and the current block text, letting the agent fix its tool call before committing.

\subsection{Layer 2: Cross-Domain Dual-Track Self-Evolution}
Across turns and sessions, Layer~2 uses a domain-agnostic evolution kernel backed by pluggable domain adapters (\texttt{manuscript}, \texttt{biostats}, \texttt{deck}, and \texttt{general\_mcp}). It combines two complementary learning tracks (illustrated with concrete examples in Table~\ref{tab:evolution_examples}):

\paragraph{Track A: Learning Domain Conventions via Corruption and Reconstruction.}
Waiting for users to manually rewrite AI drafts leaves a new workspace with a cold-start gap. Drawing inspiration from self-supervised skill training via semantic diffusion \cite{li2026skilltraining}, Track~A lets the platform learn reusable domain skills directly from existing high-quality documents (such as published clinical manuscripts, verified Statistical Analysis Plans, or executive slide decks) in three steps:
\begin{enumerate}[leftmargin=1.5em,itemsep=1pt]
  \item \textbf{Forward Corruption:} A domain adapter strips expert formatting, rhetorical transitions, methodological checks, or slide layout tags from a gold exemplar, leaving only a plain list of raw facts or analysis goals.
  \item \textbf{Skill-Conditioned Reconstruction:} The agent attempts to reconstruct the full professional text or analysis plan from the degraded skeleton using only its currently active skills.
  \item \textbf{Contrastive Skill Update \& Safety Filtering:} By comparing its reconstruction against the original exemplar, the engine identifies what domain knowledge was missing or too vague and proposes structured skill updates (\texttt{create}, \texttt{update}, \texttt{narrow}, or \texttt{merge}). Before any candidate skill is saved, an \emph{Instance--Skill Decoupling Guard} and PHI scanner automatically block rules that memorize study-specific numbers (such as sample size $N=312$ or hazard ratio $HR=0.68$), database primary keys, or patient identifiers.
\end{enumerate}

\paragraph{Track B: Zero-Template Procedural Synthesis and Backward Credit Assignment.}
Earlier versions of procedural memory relied on a static lookup dictionary that mapped known guard error codes to hand-written rule strings. To achieve true domain generalization, Heurion 2.0 removes all hand-written rule templates. Whenever a pre-write guard or domain tool verifier rejects an action and the agent recovers later in the same turn, the runtime records the failed call, the verifier's diagnostic hint, the successful recovery call, the user prompt, and the list of rules that were active in that turn.

Once an error pattern occurs at least twice, the engine updates procedural memory based on whether a matching rule was already active when the failure happened:
\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{New Failure Mode (Create):} If no rule exists for the error code, the synthesizer combines the verifier's precondition check with the observed failure-to-recovery diff to create a concise new procedural rule.
  \item \textbf{Rule Existed but Was Not Selected (Routing Miss):} If a rule for that error code already existed in the database but was not injected into the prompt (for example, the user asked to ``tighten the first sentence of Methods'' without mentioning the word ``comment'', and the paragraph happened to carry an open review comment), simply increasing the rule's evidence counter does nothing. Instead, the backward pass extracts task and section keywords from the user prompt---automatically stripping quoted document or cohort titles so triggers do not overfit to a single study name---and appends them to the rule's trigger pattern.
  \item \textbf{Rule Was Injected but Still Failed (Rule Insufficiency):} If the rule was already present in the prompt yet the agent still hit a guard error on an edge case, the engine strengthens the rule by appending the newly discovered boundary condition and recovery sequence (and optionally merges overlapping rules via an LLM refinement pass).
\end{itemize}

\paragraph{Domain-Gated MoE Routing.}
Injecting every learned rule into every prompt would quickly exhaust context budget and cause cross-domain confusion (for instance, injecting slide bullet-density rules while the agent is running a Cox survival model). Before each turn, the router scores every active procedural rule using a simple additive utility score:
\[
  \text{Utility Score} = 0.1 \times (\text{evidence}) + 5 \times (\text{keyword match}) + 8 \times (\text{live state}) + (\text{domain gate}),
\]
where \emph{keyword match} checks whether the user prompt matches the rule's base cue or learned trigger keywords, \emph{live state} checks real-time document or dataset state (such as recent human edits, open comments, tables, or sparse contingency cells), and the \emph{domain gate} adds $+4$ when a domain-tagged rule matches the active task domain (\texttt{manuscript}, \texttt{biostats}, \texttt{deck}, or \texttt{general\_mcp}) and subtracts $-20$ when it belongs to a different domain. Rules scoring below $-10$ are filtered out, and the top-scoring rules (up to 4 rules within the character budget) are injected into the turn prompt.

Across many sessions, a background meta-evolution service periodically reviews recurring execution signals and active procedural rules across the workspace, distilling the most common root causes into 2--5 short behavioral directives ($\le 100$ characters each) stored in a dynamic profile overlay (\texttt{evolved.cordis.yml}):

\section{Verified Human-AI Permission Symmetry}
\label{sec:parity}

A common flaw in enterprise AI systems is a mismatch between what a human user can do in the web UI and what the AI agent can do through tool calls. Developers often either give the agent direct database access (bypassing role checks) or expose only a small subset of endpoints.

Heurion 2.0 enforces strict permission symmetry through three mechanisms:
\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{In-Process Loopback under User Identity:} Every administrative and clinical MCP tool (\texttt{patient\_*}, \texttt{study\_*}, \texttt{doc\_manage}, \texttt{kb\_manage}, \texttt{dataset\_manage}, \texttt{memory\_manage}, \texttt{org\_manage}) executes by calling the internal Hono HTTP router in-process with a short-lived JWT minted for the current user and tagged with \texttt{X-Heurion-Via: ai}. As a result, the agent is subject to the exact same multi-tenant isolation, study role checks (PI, co-investigator, statistician, reviewer), and audit logs as the human user.
  \item \textbf{Interactive Confirmation Cards for Destructive Actions:} When an AI tool calls a high-risk or irreversible endpoint (such as deleting a document, freezing a clinical study cohort, or clearing memory), the HTTP middleware intercepts the \texttt{X-Heurion-Via: ai} header, creates a \texttt{pending\_actions} record, and displays an interactive confirmation card in the chat UI. The operation runs only after the human user clicks \emph{Confirm} in the browser.
  \item \textbf{Automated CI Parity Audit (\texttt{parity.test.ts}):} On every build, an automated test inspects the Hono router table and verifies that every registered \texttt{/api/*} route is either mapped to an MCP tool or documented in the human-only exclusion list. Any new API route missing an MCP mapping or explicit exemption fails CI immediately.
\end{enumerate}

\section{Related Work}
\label{sec:related}

\paragraph{Agent-Computer Interfaces (ACI) and Coding Agents.}
SWE-agent \cite{yang2024sweagent} and OpenHands \cite{wang2024openhands} showed that purpose-built Agent-Computer Interfaces (such as windowed file viewers and lint-guarded edit commands) work much better than raw bash shell scripting for software engineering. Heurion 2.0 brings this ACI philosophy to \textbf{collaborative rich-text and presentation CRDTs}, adding block-level concurrency guards, per-turn selective CRDT undo, and byte-preserving OOXML patch export.

\paragraph{Scientific Literature Synthesis and Fact Verification.}
Systems such as STORM \cite{shao2024storm} and PaperQA2 \cite{skarlinski2024paperqa2} automate multi-step literature search and synthesis, while FactScore \cite{min2023factscore} and ALCE \cite{gao2023alce} evaluate citation support in generated text. Rather than treating verification as an offline benchmark, Heurion 2.0 blocks unregistered citations before any write occurs (\texttt{[@c:id]}) and attaches sentence-level PubMed/PMC verification verdicts directly onto manuscript text as actionable review comments.

\paragraph{Self-Evolving Agents and Skill Training.}
Reflexion \cite{shinn2023reflexion} and MemGPT \cite{packer2023memgpt} introduced verbal reinforcement and tiered memory management for LLM agents, while Voyager \cite{wang2023voyager} built a growing skill library in Minecraft. Recently, Li et al.\ \cite{li2026skilltraining} showed that discrete text skills can be trained like model parameters through a self-supervised corruption-and-reconstruction loop. Heurion 2.0 combines self-supervised exemplar skill training (Track~A, protected by instance--skill decoupling and PHI guards) with execution-driven, zero-template procedural rule synthesis and backward credit assignment (Track~B), routing both across scientific domains without negative transfer.

\section{Conclusion}
\label{sec:conclusion}

We have presented \textbf{Heurion 2.0}, a collaborative clinical research and scientific authoring platform built on a contract-guarded dual-surface CRDT engine and a cross-domain self-evolving memory system. By replacing ad-hoc file scripting and post-hoc auditing with a shared Yjs CRDT core, deterministic pre-write guards, multi-agent PubMed/PMC claim verification, verified Human-AI Permission Symmetry, and a dual-track self-evolution loop that learns from both domain exemplars and runtime verifier feedback without hand-crafted rule templates, Heurion 2.0 provides a practical foundation for trustworthy autonomous agents in clinical and scientific workflows.
