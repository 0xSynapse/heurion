\begin{abstract}
Agent-Computer Interfaces (ACIs) have transformed autonomous software engineering by replacing raw shell manipulation with structured, lint-guarded code editors. However, scientific and clinical manuscript co-authoring still relies largely on free-form file scripting (e.g., rewriting Office Open XML \texttt{.docx} archives via \texttt{python-docx} or Markdown round-trips). In collaborative workflows, this paradigm suffers from three structural failure modes: (1) editing even a single phrase in a paragraph strips intra-paragraph publisher XML constructs such as EndNote complex citation fields (\texttt{ADDIN EN.CITE}), dynamic numbering fields, footnotes, inline equations, co-author tracked changes, and threaded comment anchors; (2) document-level optimistic version checks (\texttt{ETag}/\texttt{base\_rev}) fail in multi-turn sessions when an agent obtains a fresh revision on one paragraph and blindly overwrites an unread clinician edit or deletes a clinician-corrected statistical figure in another; and (3) file snapshots cannot selectively undo an earlier AI turn once a human co-author edits a different clause inside the same paragraph.

We present the \textbf{Heurion Agent-Document Interface (ADI)}, a collaborative document engine built on three mechanisms. First, a \emph{Dual-Surface CRDT Core} (ProseMirror + Yjs) projects a live rich-text editor for human authors and a compact Annotated Markdown view for AI agents with persistent block IDs (\texttt{\{\#id\}}), 2D logical table coordinates, atomic citations (\texttt{[@c:id]}), opaque Word field/footnote atoms (\texttt{[@w:id]}), and comment anchors (\texttt{\{\#c:id\}}). Second, \emph{Multi-Granularity Pre-Write Contracts} pair side-effect-free pre-flight validation (\texttt{doc\_validate}) with per-block read-horizon tracking (\texttt{noteSeen}), clinician-delta protection, lock-free intra-paragraph phrase commuting (\texttt{replace\_text}), and a two-tier \emph{Selective AI Turn Undo} (\texttt{revertTurn}) spanning in-memory CRDT transaction origins and cold-restart SQLite fallback. Third, an \emph{Intra-Paragraph Token-Patched OOXML Engine} (\texttt{docx-patch}) writes untouched blocks byte-for-byte from a raw slice cache (\texttt{node\_src}) while surgically patching only altered character runs inside modified paragraphs to keep surrounding Word fields, equations, bookmarks, tracked revisions, and threaded comments (\texttt{w15:paraIdParent}) intact. Evaluated across 19 open-access 2025 PubMed Central full-length clinical manuscripts ($150{,}152$ words, $2{,}719$ AST blocks across 7 study designs), Heurion ADI preserves $100.0\%$ byte identity across all $2{,}553$ untouched blocks and $100.0\%$ ($114/114$) of publisher XML constructs inside edited blocks---compared to $0.0\%$ for Markdown re-serialization and $16.7\%$ ($19/114$) for \texttt{<w:pPr>}-preserving XML paragraph scripts---at median latencies of $2.9\,\text{ms}$ for validation, $5.3\,\text{ms}$ for selective undo, and $15.5\,\text{ms}$ for patched \texttt{.docx} export, while achieving $100.0\%$ accuracy across all 8 deterministic co-editing and out-of-order undo scenarios ($152/152$ trials). In a live multi-turn agent evaluation ($171$ episodes driven by \texttt{deepseek-v4-flash} at $T=0$), Heurion ADI achieves $100.0\%$ ($57/57$) end-to-end task and OOXML fidelity---versus $33.3\%$ ($19/57$) for direct OOXML LLM editing (with $4.3\times$ fewer output tokens and $3.2\times$ lower latency on clinical table edits) and $0.0\%$ ($0/57$) for document-\texttt{ETag} MCP---autonomously self-repairing $100.0\%$ ($14/14$) of mid-session clinician edit conflicts within the same turn.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Recent advances in coding agents such as SWE-agent \cite{yang2024sweagent} and OpenHands \cite{wang2024openhands} demonstrated a foundational systems principle: autonomous large language model (LLM) agents are substantially more reliable when equipped with a purpose-built \emph{Agent-Computer Interface (ACI)}---offering compact structural views, atomic edit primitives, and immediate syntactic guardrails---rather than raw shell scripts. Yet when LLM agents are deployed to assist investigators in authoring peer-reviewed clinical and scientific manuscripts \cite{schulz2010consort,vandenbroucke2007strobe,lee2022coauthor}, most existing workflows revert to treating Office Open XML (\texttt{.docx}) \cite{ecma376ooxml} manuscripts as static disk files. Agents either convert manuscripts through lossy Markdown pipelines or generate ad-hoc scripts (e.g., \texttt{python-docx}) to mutate XML paragraphs on disk.

Deploying script-based editing in real multi-author clinical studies exposes three fundamental systems bottlenecks:
\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Intra-Paragraph Publisher XML Destruction:} Clinical manuscripts circulate among co-authors and journal production systems carrying rich OOXML structures that have no plain-Markdown equivalent: multi-run EndNote or Zotero citation fields (\texttt{ADDIN EN.CITE}), dynamic caption counters (\texttt{SEQ Table}), footnotes, inline Office Math (\texttt{<m:oMath>}), cross-reference bookmarks, content controls (\texttt{<w:sdt>}), co-author tracked changes (\texttt{<w:ins>}/\texttt{<w:del>}), and threaded Word review comments (\texttt{commentsExtended.xml}). While a careful XML script can leave \emph{untouched} paragraphs intact, rewriting the text of a modified paragraph (\texttt{paragraph.text = ...}) flattens its internal XML runs, silently destroying embedded citation fields, footnotes, equations, and comment range anchors.
  \item \textbf{Multi-Turn Blind Overwrites Beyond Document-Level \texttt{ETag}s:} In interactive co-authoring, an agent reads a manuscript at revision $r_0$, a clinician manually corrects a hazard ratio ($HR$) in paragraph $p_1$ ($r_1$), and the agent subsequently edits paragraph $p_2$ ($r_2$). Because the agent now holds the latest document revision $r_2$, standard document-level optimistic concurrency (\texttt{base\_rev == current\_rev}) allows the agent to overwrite $p_1$ from stale context memory without ever having read the clinician's edit. Even after re-reading $p_1$, an LLM asked to ``make the paragraph more concise'' frequently drops clinician-corrected numbers or newly added caveat sentences, or injects unregistered bibliographic identifiers \cite{walters2023fabrication}.
  \item \textbf{Non-Commutative File Snapshots vs.\ Intra-Paragraph Selective Undo:} Suppose an AI turn revises two paragraphs ($p_1, p_2$), a clinician immediately edits a second clause inside $p_2$, and a subsequent AI turn updates $p_3$. If the clinician then decides to revert the first AI turn, linear undo (\texttt{Ctrl+Z}) or file-level snapshot restore wipes out both the clinician's manual edit inside $p_2$ and the later AI turn in $p_3$.
\end{enumerate}

To resolve these bottlenecks without relying on fragile prompt engineering, we design and evaluate the \textbf{Heurion Agent-Document Interface (ADI)}, a contract-guarded collaborative document engine that decouples collaborative editing state from OOXML delivery archives:
\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Dual-Surface Synchronized CRDT Core (Section~\ref{sec:dualsurface}):} A server-authoritative ProseMirror + Yjs CRDT state \cite{shapiro2011crdt,nicolaescu2016yjs,litt2022peritext} projects a real-time rich-text WebSocket editor for human authors and an Annotated Markdown surface for AI agents featuring lifecycle-stable block IDs (\texttt{\{\#id\}}), 2D logical table grids, registered citation atoms (\texttt{[@c:id]}), opaque Word inline atoms (\texttt{[@w:id]}), and comment anchors (\texttt{\{\#c:id\}}).
  \item \textbf{Horizon-Tracked Co-Editing Contracts \& Two-Tier Selective Undo (Section~\ref{sec:contracts}):} Pre-write validators enforce per-block AI read horizons (\texttt{noteSeen}), post-read clinician-delta preservation, comment-anchor and native-citation protection, side-effect-free pre-flight probes (\texttt{doc\_validate}), and a two-tier \texttt{revertTurn} combining turn-scoped CRDT \texttt{Y.UndoManager} origins with persistent SQLite block fallback (\texttt{revertByNodes}) across restarts.
  \item \textbf{Intra-Paragraph Token-Patched OOXML Engine (Section~\ref{sec:ooxml}):} On \texttt{.docx} export, untouched blocks write back byte-for-byte from cached slices (\texttt{node\_src}), while modified paragraphs undergo token-aligned XML diffing (\texttt{docx-patch}) that updates only changed \texttt{<w:t>} character slices while preserving surrounding EndNote fields, footnotes, equations, bookmarks, co-author tracked changes, and threaded Word comments.
\end{itemize}

Office Open XML (\texttt{.docx}) archives interleave content with layout caches, RSIDs, namespace prefixes, and split character runs, making raw XML both token-inefficient and error-prone for LLMs. Conversely, converting a manuscript to plain Markdown discards inline structural metadata. As shown in Figure~\ref{fig:adi_architecture}, Heurion ADI resolves this tension by maintaining a single server-authoritative Yjs CRDT document (\texttt{Y.Doc}) \cite{nicolaescu2016yjs} backed by SQLite snapshots and an append-only block change log (\texttt{node\_changes}), projecting two synchronized views:

\paragraph{Lifecycle-Stable Block Addressing (\texttt{\{\#id\}}) and 2D Logical Table Grids.}
Every structural node (heading, paragraph, list item, table, cell paragraph, or figure) carries a persistent short identifier \texttt{\{\#id\}}. When a browser user splits a paragraph or pastes blocks, a server transaction automatically assigns fresh unique IDs to deduplicate collisions. Multi-column clinical tables containing horizontal (\texttt{colspan}) and vertical (\texttt{rowspan}) header merges are projected through a unified 2D logical coordinate mapper (\texttt{readGrid}): merged continuations render explicitly as \texttt{<} and \texttt{\textasciicircum} in the agent's Markdown view, ensuring that the $(r, c)$ coordinates read by the agent map identically to \texttt{table\_set\_cells}, \texttt{table\_merge\_cells}, and \texttt{table\_split\_cell}.

\paragraph{Opaque Word Inline Atoms (\texttt{[@w:id]}) vs.\ Registered Citations (\texttt{[@c:id]}).}
To let agents read and edit paragraphs containing complex Word constructs without exposing raw XML, \texttt{importDocx} lifts non-textual inline OOXML structures---footnotes (\texttt{<w:footnote\allowbreak Reference>}), simple fields (\texttt{<w:fldSimple>}, such as \texttt{SEQ Table}), and multi-run complex fields (\texttt{w:fldChar} \texttt{begin}\dots\texttt{end}, such as EndNote \texttt{ADDIN EN.CITE})---into atomic inline nodes rendered in Annotated Markdown as \texttt{[@w:w1]} alongside a read-only legend at the bottom of the agent's viewport:
\begin{lstlisting}[style=heurionspec]
{#p8f2} Supplementary Table [@w:w1] summarizes baseline adjudication[@w:w2] for the cohort.
---
[@w:w1] Field code (displayed as "1")
[@w:w2] Footnote: Adjudicated per independent clinical endpoint committee charter.
\end{lstlisting}
Platform-managed citations are similarly represented as atomic nodes \texttt{[@c:cite\_id]} registered via Crossref, PubMed, or OpenAlex, whereas open review comment spans appear inline with thread IDs and quoted snippets.

\section{Multi-Granularity Co-Editing Contracts and Selective Undo}
\label{sec:contracts}

All AI mutations execute through atomic batches (\texttt{doc\_edit}) supporting both direct application (\texttt{mode: "apply"}) and native tracked-changes proposals (\texttt{mode: "suggest"}). Before any Yjs transaction is committed, \texttt{OpService.simulate} validates the entire batch against an ephemeral ProseMirror state; if any operation fails, the batch aborts atomically and returns a structured \texttt{OpError} containing an error code, recovery hint, and current block text. Agents can also invoke this exact pipeline without side effects via \texttt{doc\_validate} (or \texttt{dry\_run: true}).

\subsection{Per-Block Read Horizons (\texttt{noteSeen}) and Clinician-Delta Protection}
Document-level optimistic locking (\texttt{base\_rev}) only detects edits that occur \emph{after} the latest revision number held by the agent. In multi-turn sessions, an agent often edits section~B (receiving fresh revision $r_2$) while holding stale context for section~A, which a clinician edited earlier at $r_1 < r_2$. Heurion ADI closes this gap at three granularities:
\begin{enumerate}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Per-Block Read Horizon (\texttt{noteSeen}):} Whenever \texttt{doc\_read} returns block $b$ at revision $r$, the server records $\text{seen}(b) \leftarrow r$. Even if an agent supplies the latest document \texttt{base\_rev}, any whole-block write (\texttt{replace\_block}, \texttt{delete}) on $b$ is rejected with \texttt{conflict\_user\_edited} if a human modified $b$ at any revision $r' > \text{seen}(b)$, returning the clinician's updated text in \texttt{extra.current}.
  \item \textbf{Post-Read Clinician-Delta Guard:} Clinicians frequently correct statistical figures (e.g., changing \texttt{HR 1.82} to \texttt{HR 1.12}) or append methodological caveats, then ask the AI to polish prose. Even \emph{after} the AI has re-read the block ($r' \le \text{seen}(b)$), the validator extracts user-authored numeric tokens and added sentences from \texttt{node\_changes} and blocks any AI \texttt{replace\_block} or \texttt{replace\_text} that silently drops them (\texttt{conflict\_user\_edited}).
  \item \textbf{Lock-Free Intra-Paragraph Commuting (\texttt{replace\_text}):} For surgical phrase edits, the literal \texttt{find} string acts as a fine-grained precondition: if a clinician edited clause~1 of paragraph $b$ after \texttt{base\_rev}, an AI \texttt{replace\_text} targeting clause~2 of $b$ still matches uniquely and commits cleanly, slicing only the target character offsets in ProseMirror and Yjs while preserving surrounding bold/italic marks, \texttt{[@c:id]} citations, and comment highlights \cite{litt2022peritext}. Ambiguous multi-matches require an explicit \texttt{occurrence} index (\texttt{ambiguous\_match}).
\end{enumerate}

\subsection{Citation, Opaque Field, Comment-Anchor, and Permission Guards}
Four domain invariants prevent silent corruption of scholarly metadata:
(i) \emph{Pre-Write Citation Guard:} scans outgoing text for bare DOIs, bare PMIDs, or hand-typed bibliography lines (\texttt{citation\_not\_registered}), and blocks unknown \texttt{[@c:id]} tokens (\texttt{citation\_unknown});
(ii) \emph{Native Reference \& Field Protection:} forbids AI edits from hijacking pre-existing numbered citations such as \texttt{[1]} into platform citations (\texttt{existing\_citation}, which would corrupt external reference lists) or fabricating non-existent Word field markers such as \texttt{[@w:w99]};
(iii) \emph{Comment-Anchor Preservation:} blocks edits that erase the text anchored by an open review comment unless the batch explicitly passes \texttt{ack\_comments} or executes as the designated reply turn (\texttt{anchor\_has\_open\_comments}), while \texttt{merge} automatically migrates comment anchors and footnotes across joined paragraphs; and
(iv) \emph{In-Process Permission Symmetry:} every MCP tool executes in-process through the Hono HTTP router under a short-lived user JWT tagged with \texttt{X-Heurion-Via: ai} (audited in CI by \texttt{parity.test.ts}), gating destructive endpoints behind interactive UI confirmation cards.

\subsection{Two-Tier Per-Turn Selective AI Undo (\texttt{revertTurn})}
To allow clinicians to undo a specific prior AI turn $T_k$ out of order without losing subsequent human or AI edits, \texttt{Documents.revertTurn} combines two complementary tiers:
\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
  \item \textbf{Tier 1 (In-Memory Intra-Paragraph CRDT Undo):} Every AI commit tags its Yjs transaction with a turn-specific \texttt{ServerOrigin} (\texttt{turnId: $T_k$}) tracked by a dedicated \texttt{Y.UndoManager} scope. Invoking \texttt{revertTurn($T_k$)} inverts only the Yjs item insertions and deletions originated by $T_k$, preserving concurrent human edits even inside the exact same paragraph as well as later AI turns $T_{k' > k}$.
  \item \textbf{Tier 2 (Persistent Cold-Restart Block Fallback):} Before an AI turn's first mutation, the engine persists the pre-turn Yjs state vector and per-block change manifest in SQLite. If the server restarts before \texttt{revertTurn($T_k$)} is invoked (evicting in-memory \texttt{Y.UndoManager} instances), \texttt{revertByNodes} reconstructs the pre-turn baseline tree, removes blocks added by $T_k$, restores modified or deleted blocks to their pre-turn state, and safely skips any block modified by a human after $T_k$ (\emph{user-priority skip}).
\end{itemize}

\section{Intra-Paragraph Token-Patched OOXML Round-Trip Engine}
\label{sec:ooxml}

Caching raw XML slices (\texttt{node\_src}) per imported block guarantees byte-identical export for \emph{untouched} blocks, but falls back to full re-serialization as soon as an agent fixes a typo inside a paragraph. To preserve publisher XML inside \emph{modified} blocks, Heurion ADI introduces a token-level XML patcher (\texttt{docx-patch.ts}).

\paragraph{Token-Aligned Run Slicing (\texttt{docx-patch}).}
During export of a modified paragraph $b$, \texttt{docx-patch} parses its original raw XML \texttt{node\_src($b$)} into a structural run tree (\texttt{RNode}) while simultaneously flattening both the import-time baseline ProseMirror node $b_0$ and the current ProseMirror node $b_t$ into character-and-atom token sequences (\texttt{Tok}, carrying text characters, mark signatures, \texttt{[@w:id]} atoms, and \texttt{[@c:id]} citations). After verifying 1-to-1 token alignment between \texttt{node\_src($b$)} and $b_0$, a minimal sequence diff between $b_0$ and $b_t$ patches \texttt{node\_src($b$)} directly:
\begin{enumerate}[leftmargin=1.5em,itemsep=1pt]
  \item Unchanged character runs keep their exact original \texttt{<w:r>} XML, preserving unmodeled run properties (custom fonts, theme colors, kerning, proofing flags, RSIDs).
  \item Newly inserted characters inherit the non-modeled \texttt{<w:rPr>} attributes of the adjacent run (mirroring interactive typing in Microsoft Word), splitting into a sibling run only when explicit formatting marks (e.g., bold/italic) change.
  \item Non-textual XML siblings and containers---including complex fields (\texttt{w:fldChar begin\dots end} for EndNote \texttt{ADDIN EN.CITE}), \texttt{<w:fldSimple>} counters, \texttt{<w:footnote\allowbreak Reference>}, bookmarks (\texttt{<w:bookmark\allowbreak Start/End>}), permission ranges (\texttt{<w:perm\allowbreak Start/End>}), symbols (\texttt{<w:sym>}), inline OMML equations (\texttt{<m:oMath>}), outer content controls (\texttt{<w:sdt>}), and nested or tracked table rows (\texttt{<w:trPr><w:ins>})---remain frozen in their exact original XML positions.
\end{enumerate}

\paragraph{Bidirectional Word Tracked Changes and Threaded Comments.}
Co-author Word tracked changes (\texttt{<w:del>}/\texttt{<w:ins>}) import as paired ProseMirror blocks (\texttt{suggest: "delete" | "insert"}, linked via \texttt{suggest\_of}) displaying author attribution in the agent's view. Pre-write guards block AI edits that collide with a co-author's tracked span while allowing edits elsewhere in the same paragraph, which \texttt{docx-patch} writes back into the original XML without altering the co-author's \texttt{w:author} revision tags. Conversely, AI edits made under \texttt{mode: "suggest"} export as native Word \texttt{<w:del>}/\texttt{<w:ins>} pairs while stripping \texttt{w14:paraId} from the deleted twin so every paragraph in \texttt{word/document.xml} retains a unique \texttt{w14:paraId}. Similarly, Word comments and replies (\texttt{comments.xml} + \texttt{commentsExtended.xml}) import as anchored threads; AI thread replies export as child \texttt{<w:comment>} entries linked to the root comment's paragraph ID via \texttt{w15:paraIdParent}, with \texttt{<w:commentRangeStart/End>} paired cleanly even when comments and \texttt{suggest} revisions coexist in the same paragraph.

\section{Empirical Evaluation}
\label{sec:evaluation}

We evaluate Heurion ADI across two clean-room benchmark suites (\path{paper/benchmarks/run-clean-adi-eval.ts} and \path{paper/benchmarks/run-online-adi-llm-eval.ts}) over all \textbf{19 open-access 2025 PubMed Central (PMC) full-length clinical manuscripts} in our evaluation corpus, spanning 7 study designs (randomized controlled trials, retrospective cohorts, case-control, diagnostic accuracy, cross-sectional, meta-analyses, and translational studies). Across the 19 full-text manuscripts, the corpus totals \textbf{150,152 words} (mean $7{,}903$ words/manuscript) and \textbf{2,719 AST blocks} (mean $143$ blocks/manuscript; 18 of 19 manuscripts contain multi-column clinical tables). All baselines execute as real code pipelines or live tool-calling LLM loops over the exact same full-length \texttt{.docx} archives without hand-estimated numbers or prompt handicapping.

\subsection{Experiment 1: Publisher OOXML Round-Trip Fidelity and Latency}
For each of the 19 full-length PMC manuscripts, we construct a valid OOXML \texttt{.docx} archive with unique \texttt{w14:paraId} attributes on every paragraph plus publisher collaboration blocks containing: (1) an EndNote \texttt{ADDIN EN.CITE} complex field, (2) a \texttt{SEQ Table} dynamic field and \texttt{<w:footnoteReference>} (\texttt{footnotes.xml}), (3) a bookmark range, \texttt{<w:sym>}, highlight run, and inline \texttt{<m:oMath>} formula, (4) a \texttt{<w:sdt>} structured content control, (5) co-author \texttt{<w:del>}/\texttt{<w:ins>} tracked changes and a tracked nested table row (\texttt{<w:trPr><w:ins>}), and (6) a threaded co-author comment pair (\texttt{comments.xml} + \texttt{commentsExtended.xml} \texttt{w15:paraIdParent}). Each pipeline applies the exact same revision batch (editing an organic PMC prose paragraph plus text inside each of the 6 publisher constructs, alongside a tracked revision). We compare three executable pipelines:
\begin{itemize}[leftmargin=1.5em,itemsep=1pt]

\subsection{Experiment 3: Live Multi-Turn LLM Co-Editing and Within-Turn Self-Repair}
\label{sec:online_llm}
Deterministic traces validate engine invariants, but leave open a practical HCI/systems question: when a real LLM drives multi-turn tool calls, can it interpret ADI's structured guard rejections (\texttt{code}, \texttt{hint}, \texttt{current}) and converge within the turn without corrupting \texttt{.docx} archives? We evaluate an unmodified cloud reasoning model (\texttt{deepseek-v4-flash}, Anthropic Messages tool-use protocol, $T=0$, up to $5$ steps/turn) across all $N=19$ full-length PMC clinical manuscripts on three multi-step co-authoring workloads ($57$ episodes per arm; $171$ live multi-turn episodes total):
\begin{itemize}[leftmargin=1.5em,itemsep=1pt]
  \item \textbf{W1 (Publisher-Rich Paragraph Revision):} Revise clinical wording and follow-up duration inside a paragraph containing an EndNote \texttt{ADDIN EN.CITE} complex field, a \texttt{<w:footnoteReference>}, and an inline \texttt{<m:oMath>} formula ($\alpha=0.05$).

In Turn~3, the user asks the agent to tighten $p_1$ via \texttt{replace\_block} to report a 24-month window; success requires both applying the 24-month revision and preserving the clinician's concurrent $HR~1.12$ edit.
  \item \textbf{W3 (Merged Clinical Table Header + Anchored Comment):} Rename a merged header cell (\texttt{colspan}/\texttt{rowspan}) in each manuscript's clinical table and rewrite a prose sentence anchored by an open reviewer comment while maintaining strict \texttt{DOMParser} XML validity and balanced comment range markers on export.

\section{Related Work and Conclusion}
\label{sec:related_conclusion}

\paragraph{Related Work.}
SWE-agent \cite{yang2024sweagent} and OpenHands \cite{wang2024openhands} established Agent-Computer Interfaces for plain-text source code, while STORM \cite{shao2024storm} and PaperQA2 \cite{skarlinski2024paperqa2} automate read-only literature synthesis and CoAuthor \cite{lee2022coauthor} studies human-AI text generation in flat editors. On the collaborative systems side, Yjs \cite{nicolaescu2016yjs} and Peritext \cite{litt2022peritext} formalize rich-text CRDT convergence for human co-editors, but do not address asymmetric AI batch mutations, multi-turn agent read horizons, or lossless round-tripping with publisher OOXML \cite{ecma376ooxml} fields and tracked revisions. Heurion ADI bridges these two lines of work, turning collaborative CRDTs and token-patched OOXML into a contract-guarded interface for scientific agents.

\paragraph{Conclusion.}
Replacing free-form file scripting with a dual-surface Yjs CRDT core, per-block horizon and clinician-delta contracts, two-tier selective turn undo, and intra-paragraph token-patched OOXML export eliminates structural formatting loss and silent human-edit overwrites in collaborative clinical authoring, providing a clean systems foundation for higher-level scientific verification and review workflows.
