# 深度审稿独立产品方案（草案）

> 状态：草案，2026-11-08。基于对现有代码的摸底与单篇调用量实测；定价与数据政策中的若干项待决策（见文末）。

## 1. 定位

把平台已有的「全文深度审稿」做成独立入口：用户上传稿件 → 得到带批注的审稿报告 → 按次付费。目标是引流：审稿的使用频率和覆盖人群都远大于队列研究，且不需要先准备数据就能体会价值。

- **独立入口，不独立系统**：落地页、上传、报告页、付费是新的；文档模型、审稿、批注、导出全部复用平台（审稿依赖批注锚点、「按意见修改」走操作层、正式引用走 `insert_citation`，另起一套等于重写，也违反「AI 写入只能经操作层」的约定）。
- **转化钩子放在「修改」**：免费/付费只覆盖审稿报告；「按意见让 AI 改写」「插入推荐文献」「邀请合作者」进入完整写作平台。审稿用户最自然的下一步是写作，不是队列研究，首要观察指标是「审稿 → 用编辑器修改」的转化率。
- **报得准优先于报得全**：首次使用的用户没有「误报免报」偏好，默认只展示 critical / major 两级。

## 2. 现状摸底

| 环节 | 现状 | 可复用程度 | 缺口 |
|---|---|---|---|
| 上传导入 | `POST /api/docs` 支持 docx / pptx / pdf（`http/api.ts:1389`）。docx 走 `importDocx`；PDF 主路径为 doc-parser（Docling），失败退回 pdftohtml + OCR | 高 | PDF 导入会顺带把原件写进资料库 KB（`api.ts:1417`），删文档不连带删除，与 30 天删除冲突 |
| 账号 | 自助注册：用户名 + 密码 + 防机器人题，不要求邮箱；自动建个人租户 | 中 | 没有游客或免密登录；付费和找回需要邮箱 |
| 审稿接口 | `POST /api/docs/:id/deep-review`，同步长请求，模式写死为 `heurion_evolved` | 中 | 没有任务队列、进度、限流；模型函数借用 skillTrainer / evolution / mail 的 `complete`（`api.ts:1929`），接线脆弱 |
| 结果呈现 | 审稿发现写入 `comments` 表并加 `comment` mark；`GET /api/docs/:id/html` 可服务端渲染，`export.docx` 会把未解决批注写进 Word | 高 | 前端的审稿统计只存在 localStorage，需要落库；需要一个不依赖编辑器的只读报告页 |
| 计量与计费 | 无任何 quota / credit / billing / payment 代码，不记录模型 token 用量 | 无 | 全部新建。`apps/site/aegis-cloud` 的计费属于 Aegis 产品，不共享 |
| 保留与删除 | 删除进回收站，30 天后清理（`purgeTrash(30)`）；`audit_events` 保留 365 天 | 中 | 没有「创建满 30 天自动删除」；deep-review 不写审计；没有条款或同意接受机制 |
| 数据外发 | `heurion.cordis.yml` 只约束 dsh 回合；deepReview 直接调 DeepSeek（`harness/complete.ts`，默认模型 `deepseek-flash`） | — | 稿件全文会发给 DeepSeek，必须在落地页披露 |
| 文献核查（通道 A） | 不在一键审稿里：`pass_a_citation` 只有类型定义，没有产出；文献比对只在「核对全部论断」（`/verify`，完整 Agent 回合）里做 | 低 | 要主打「每条问题有文献证据」，必须把它接进审稿流程 |

## 3. 单篇成本实测

方法：用一篇按常见比例构造的约 5000 词英文稿件（3 张表）调用 `runFourStageDeepReview`（`heurion_evolved`），`complete` 换成只计数的函数。

| 结构 | 模型调用次数 | 输入 token（估） |
|---|---|---|
| 只有一级标题（6 节） | 6 | 约 1.0 万 |
| 带小标题（16 节，较常见） | 16 | 约 1.7 万 |

- 调用次数等于章节数（每个标题一节），且方法 / 结果下的每个小节都会重发全部表格，所以小标题越多越贵。
- 输出未实测，按每次 200–1500 token 粗估，一篇约 0.5–1.5 万。
- 中文稿件每字 token 更多，同样字数成本更高。
- 单次调用超时 180 秒、最多输出 8000 token，章节并行调用；接口是同步等待，没有总超时与重试控制。
- 接入文献核查后，每条外部论断还要检索 PubMed / Crossref 并多一轮模型比对，成本和耗时会明显上升，需单独测。

**结论**：定价前必须先上线 token 计量，用真实稿件统计单篇成本分布（按长度分档），再定包价。

## 4. 产品形态

1. 落地页：说明能查什么（附一份示例报告）、数据去向与保留政策、价格。
2. 上传：docx / PDF，上传前勾选同意（见第 6 节）；限制篇幅（字数或页数上限）。
3. 审稿：异步任务，页面显示进度；失败不扣额度。
4. 报告页：只读视图，问题按严重度排序，点击定位原文；可下载带批注的 Word。
5. 付费墙：首篇免费（只展示 critical / major），之后按额度包扣减。
6. 转化：报告页每条问题旁「在编辑器中修改」，进入完整平台。

## 5. 需要新建或改动的模块

1. **token 计量**（最先做）：`makeComplete` 记录每次调用的输入 / 输出 token，按文档和用户汇总。
2. **审稿任务化**：把 deep-review 改成后台任务（排队、进度、总超时、失败重试），按用户和全局限流；模型函数显式注入，不再借用其它服务的 `complete`。
3. **轻量账号**：用邮箱免密登录（magic link）或「先审后注册」；付费必须绑定邮箱（收据、找回）。
4. **额度与支付**：额度流水表（充值、扣减、退回），支付渠道 webhook 入账；审稿成功才扣减。海外用 Stripe / Paddle，国内需要微信 / 支付宝。
5. **报告页**：基于 `GET /api/docs/:id/html` 与 comments 渲染只读页；审稿统计从 localStorage 改为落库。
6. **保留与删除**：审稿产品的文档按「创建后 30 天」自动彻底删除，连同 assets、doc_packages 和 KB 副本（审稿入口导入 PDF 时不再写 KB）；deep-review 写审计。
7. **同意机制**：条款版本与同意记录落库；服务保留与训练使用分开勾选。
8. **自演进的数据来源**：以用户反馈为主（误报申辩、采纳修复，已有 `evolveFromReviewComment`）；全文只在用户勾选训练同意且去标识化后使用。注意现有边界规则按 owner 存储，跨用户的全局演进需要单独设计聚合与脱敏。
9. **文献核查接入**（第二阶段）：把 `/verify` 里的通道 A 能力抽成可在审稿任务里调用的步骤，结果同样落成批注。
10. **学科扩展**（第三阶段）：见第 7 节。

## 6. 数据政策（需法务确认）

- **保留**：稿件为提供服务保留 30 天，用户可随时删除，到期自动彻底删除。
- **训练**：单独勾选同意，默认不勾；进训练集前去标识化（患者信息、作者信息）。依据：GDPR 与《个人信息保护法》都要求明确同意，仅写在服务条款里不够。
- **代传他人稿件**：条款明确禁止上传自己无权处理的稿件（如正在审的投稿）；期刊普遍禁止审稿人把稿件交给 AI 工具，拿这类稿件训练会带来保密和声誉风险。
- **第三方处理**：稿件全文会发给模型服务商（目前是 DeepSeek），外部检索会把论断片段发给 PubMed / Europe PMC / Crossref，落地页需列明。面向欧美用户时，还要评估把稿件发往中国服务商的数据跨境问题，可能需要按地区选择模型服务商。

## 7. 学科扩展

三条核查（数值与文献对齐、前后自洽、论断缺引用）本身不限于医学，但目前有三处绑定医学：

- **提示词**：章节审查提示写死了 pCR、OS、HR、Mean±SD vs SEM、CONSORT / STROBE 等医学概念（`claims/service.ts:1076-1082`）。
- **规则检查**：`auditInternalConsistency`、`auditSpinAndGuidelines` 等按临床研究的样本量、统计报告规范设计。
- **章节角色**：按 引言 / 方法 / 结果 / 讨论 结构判断哪里要严查缺引用；文献检索以 PubMed / Europe PMC 为主（只覆盖生物医学），其它学科需要 OpenAlex / Crossref（已有接入），计算机、物理还需要 arXiv。

分阶段：医学与生命科学 → 其它实证学科（按学科切换提示词与检索源）→ 其余学科先标测试版，只开不依赖领域知识的核查（如前后自洽）。每个学科建误报率评测集（可参照 `eval/claims.jsonl`），达标再正式开放。

## 8. 里程碑

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| P0 内测 | token 计量、审稿任务化、只读报告页、手动发放额度；医学稿件 | 真实稿件的单篇成本分布、耗时、误报率有数据 |
| P1 公开上线 | 落地页、轻量账号、支付与额度、30 天删除、同意机制、审计 | 支付闭环跑通；数据政策经法务确认 |
| P2 证据化 | 文献核查接入审稿任务 | 文献类问题有可点开的证据 |
| P3 扩学科 | 学科识别、分学科提示词与检索源、分学科评测 | 各学科误报率达标 |

## 9. 待决策

1. 定价：1.99 美元 5 篇在按笔收费渠道下手续费约占 18%，建议等 P0 成本数据出来后再定（候选：更大的包，或充值点数）。
2. 首篇免费的范围：完整展示 critical / major，还是只展示问题数量和一条示例。
3. 国内用户是否首发：决定是否要接微信 / 支付宝、是否需要人民币定价。
4. 模型服务商是否按地区区分（数据跨境）。
5. 免费层是否接入文献核查（成本最高的一环）。
