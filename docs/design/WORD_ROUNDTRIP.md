# Word 回流合并设计方案（来源等级第 5 期）

> 状态：待确认（2026-11-13）。关联：`docs/design/PROVENANCE.md`（第 7 节第 5 期）、论文一「人的修改不被覆盖」在真实流程里的证明。

## 1. 要解决的问题

医生的真实流程（问卷与访谈）：稿件导出成 Word → 微信发给导师 → 导师在 Word / WPS 里用修订和批注改 → 发回来。这期间平台里的稿件可能也在变（作者自己、AI 都在改）。

现在发回来的 Word 只能**新建一份文档**导入，结果是：

- 平台里那份和导师改的那份分成两份，作者只能手工对照合并（问卷里的高频痛点「多个版本需要手动合并」）；
- 平台里导出之后的修改（包括 AI 的修改）与导师的修改互相看不见，合并时很容易冲掉一方。

**目标**：把发回来的 Word 导回**同一份文档**，三方合并：

- **基础版**：导出那一刻平台里的内容；
- **平台版**：现在平台里的内容（导出之后作者、AI 的修改）；
- **Word 版**：导师改完发回来的文件（含修订、批注、新加的 EndNote 引用）。

保证：两边各自的修改都保留；两边改了同一段时不静默覆盖任何一方，交给作者决定；导师的修改在平台里是「人写的」，AI 之后不能暗改（来源规则自动生效）。

## 2. 现状与缺口

| 已有 | 缺口 |
|---|---|
| 导入 Word：修订 → 待采纳修订块（记合作者姓名 `suggest_author`）；批注 → 评论线程；EndNote / Zotero 域、脚注 → `[@w:]` 原子 | 只能新建文档，不能导回同一份 |
| 导出 Word：没改的块原样写回原始 XML（`node_src`），改过的段内修补（`docx-patch`）；平台评论导出为 Word 批注 | **导出的文件里没有记下来自哪份文档、哪个版本**；平台新建的段落没有段落 ID，导回来时认不出哪段对应哪段 |
| 导入稿的段落保留 Word 原来的 `w14:paraId` | Word 与 WPS 是否在编辑后保留 `w14:paraId`、自定义文档属性，**需要实测**（WPS 尤其不确定） |

## 3. 设计

### 3.1 导出时留下「回执」

每次导出 docx：

1. 生成导出记录 `doc_exports(id, doc_id, rev, state, para_map, comment_map, created_at, by)`：
   - `state`：导出那一刻的文档状态（Yjs 快照），就是三方合并的**基础版**；
   - `para_map`：Word 段落 ID → 平台块 id。平台新建、没有 `w14:paraId` 的段落，导出时按块 id 生成稳定的 ID 写上；
   - `comment_map`：Word 批注 id → 平台评论线程 id（导师在 Word 里回复平台评论时，回复能挂回原线程）。
   - 每份文档保留最近 20 次导出记录。
2. 在文件的自定义文档属性（`docProps/custom.xml`）里写 `HeurionExport = <导出记录 id>`。对用户不可见，不影响打开和打印。

### 3.2 导回时认出对应关系

用户在**这份文档里**点「导入回传稿」上传 docx（目标文档由入口确定，不靠文件猜）：

1. **找基础版**：读 `HeurionExport` → 导出记录。读不到（被 WPS 丢掉、或是更早的副本）时，把各次导出记录的段落文字与回传稿逐一比对，取最相近的一次作基础版，并在预览里注明「按内容推断的导出版本」。
2. **段落对应**：先按 `para_map` 里的段落 ID 对；对不上的（ID 丢失或被改写）按段落顺序做文字相似度对齐（最长公共子序列，相似度 ≥ 0.6 算同一段）。
3. 回传稿用现有的 `importDocx` 解析成模型：修订 → 带作者的待采纳修订，批注 → 线程，域 → 原子。

### 3.3 逐段三方合并

以基础版的每一块为单位比较「平台版 vs 基础版」「Word 版 vs 基础版」：

| 平台版 | Word 版 | 合并结果 |
|---|---|---|
| 没改 | 没改 | 不动 |
| 没改 | **改了**（直接改） | 采用 Word 版。导师是人类合作者，算「人写的」，按段落记修改人 |
| 没改 | **改了**（修订模式） | 原样带入为待采纳修订，作者为 Word 里的修订人。导师用修订就是「请你确认」 |
| **改了** | 没改 | 保留平台版 |
| **改了** | **改了** | **冲突**：保留平台版，把 Word 版作为待采纳修订放在旁边（作者 = 导师），并在该段加一条评论「这段平台和 Word 里都改过」，由作者采纳或拒绝。不静默选任何一方 |
| 没改 | 删掉了 | 变成待删除修订（未用修订模式的删除也不直接删：误删的代价大） |
| 改了 | 删掉了 | 冲突：保留平台版并加评论 |
| — | 新增的段落 | 按对应位置插入；修订模式插入的仍是待采纳修订 |
| 新增的段落 | — | 保留 |

批注：

- 回传稿里新增的批注 → 新评论线程，作者为 Word 里的批注人；
- 对平台评论的回复（按 `comment_map`）→ 挂到原线程下；
- 在 Word 里标为「已解决」的平台评论 → 线程标为已解决。

### 3.4 Word 结构与文件包

- 采用 Word 版的段落：它在回传稿里的原始 XML 写入 `node_src`，导师新插入的 EndNote 引用、脚注、公式下次导出原样保留。
- 回传稿的文件包作为新的原始文件包（`doc_packages`）：之后的导出以导师那份为底（样式、编号、EndNote 参考文献表都是最新的）。只存在于平台版的块，导出时按现有方式生成。
- **需要实测的风险**：两份文件包的列表编号定义（`numId`）可能不一致。第一步实现时，平台独有的列表块按回传稿的编号定义重新映射；映射不了的退回普通段落，并在预览里提示。

### 3.5 来源等级

- 整次合并作为一次提交：写者为上传的用户，操作 `word_roundtrip`，记下回传稿文件名与基础版。
- Word 版带来的文字一律是「人写的」（不加 AI 标记）；冲突旁的 Word 版修订作者为导师。
- 由于这次提交按「用户修改」记入节点变更，AI 下次改这些段落时，冲突守卫（`noteSeen`）会要求它先读新内容；医生改过的数字受「人写的文字只能安全小改」保护——**第 1–4 期的规则在回流场景下自动生效，不需要另写**。

### 3.6 先预览，再合并

上传后先显示预览，不改文档：

> 回传稿：《XXX_导师修改.docx》，对应 11 月 12 日 15:30 的导出（v14）
> - 12 段只在 Word 里改过 → 采用导师的修改（其中 7 段是修订，需要你采纳）
> - 5 段只在平台里改过 → 保留
> - **2 段两边都改过** → 两个版本都保留，等你选（列出这两段）
> - 4 条新批注、3 条对平台评论的回复
> - 1 处列表编号无法对应，已按普通段落处理

确认后执行合并，并打一个版本（随时可以回滚到合并前）。

### 3.7 接口与 AI

- `POST /api/docs/:id/roundtrip/preview`（上传 docx，返回预览）、`POST /api/docs/:id/roundtrip/apply`（按预览 id 执行）。
- AI 对等：`doc_manage` 增加 `import_roundtrip`（file_path 指向工作区里的 docx），**需要用户确认卡**：它会改动大量内容。
- 导出接口加写导出记录与自定义属性；`docx-export` 给没有段落 ID 的段落生成稳定 ID。

## 4. 对论文的意义

这一期把「人的修改不被覆盖」从实时协同场景，搬到了医生真实的工作方式里（微信传稿、Word 修订），可以直接做论文一的实验：

- 用公开稿件生成「平台改 + 导师在 Word 里改」的成对修改，度量：双方修改的保留率、冲突检出的准确率、Word 结构（EndNote 域、脚注、修订、批注）的保留率；
- 对照「把回传稿当新文档导入再手工对照」与「整份覆盖」两种现状做法。

| 步 | 内容 | 验证 |

| 5a | 导出记录、稳定段落 ID、自定义属性 | **先实测**：用 Word（网页版即可）与 WPS 打开导出文件、改几处、保存，检查段落 ID 与自定义属性是否保留；结论决定 3.2 的对齐以哪条为主 |

## 6. 已确认的决定（2026-11-13）

1. **导师未用修订模式的直接修改**：直接采用（导师是人类合作者，算人写的）；预览里列出，合并后可整体回滚。
2. **冲突**：保留平台版，Word 版作为待采纳修订放在旁边并加评论，由作者决定。
3. **没有导出回执的回传稿**：按内容推断基础版，预览里注明「按内容推断」。
4. **不做事先实测**：段落 ID 与文字相似度对齐两条路径都保留，ID 丢失时用文字对齐兜底。每次合并记录多少段按 ID 对上、多少段靠文字对齐、有没有读到导出回执（与 `REVIEW_QUALITY.md` 同一思路），从真实使用里看 WPS 的情况，后备路径出错多时再加强。
   - 按文字对齐的段落在预览里标出，请用户核对；按 ID 对上的不标。
   - 相似度低于阈值、对不上任何原段落的，不强行配对：作为导师新写的段落加入，原段落按导师删除处理，两者都以待采纳修订出现。

实施顺序：先完成论文一大纲（第 5 期在论文里对应「真实流程中人的修改不被覆盖」的实验，按实验需要确定做到什么程度），再实施 5a–5d。
