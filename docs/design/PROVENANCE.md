# 来源等级（Provenance）设计方案

> 状态：已确认（2026-11-13），按「分期实施」逐期落地，每期单独提交。
> 关联：论文一（`paper/`）的核心主张；`docs/design/AI_PERMISSIONS.md`；`docs/design/IMAGING_STUDIES.md` 中的测量原子与 `cohort_stat`。

## 1. 要解决的问题

医生最怕 AI 改稿时弄错三样东西：**数字、引用、原意**；其次是自己或导师改过的内容被冲掉（问卷与访谈，见 `apps/platform/src/survey/`）。

平台已经有一组守卫分别管这些事（`ops/service.ts`）：

| 现有守卫 | 管什么 |
|---|---|
| `guardConflicts`（`noteSeen` 读取范围） | AI 没读过的人工修改不能整块覆盖 |
| `guardUserContent` | AI 改写时不能删掉人改过的数字和补充的句子 |
| `guardCitations` / `guardExistingCitations` / `guardCitationRetention` / `guardCitationSupport` | 不能手写 DOI / PMID；引用必须登记；已有引用不能丢；引用摘要要和句子主张对得上 |
| `guardMeasurements` / `guardMeasurementRetention` | 测量值必须绑定来源；已绑定的不能丢 |
| `guardPending` / `guardAnchors` | 不碰合作者的待采纳修订；不删开放评论的锚点 |

它们各管一类，是逐个补出来的。问题有两个：

1. **没有统一原理**：每条守卫的边界靠经验，说不清「还漏了什么」。
2. **只到块级**：`node_changes` 只记「哪个块被谁改过」，一段里哪些字是人写的、哪些是 AI 写的，只能从 `replace_text` 日志里猜（`guardUserContent` 的做法）。

## 2. 核心原理

### 2.1 来源等级

稿件里的每一处内容都带一个来源：

| 内容 | 来源等级（高 → 低） | 表示方式 |
|---|---|---|
| 文字 | **人**：医生输入、导入的原稿、医生采纳或确认过的 AI 文字 | 文字上的 `prov` 标记 `by=human`，或没有标记（见 6.1） |
| 文字 | **AI 未确认**：AI 写入、还没人确认 | `prov` 标记 `by=ai`，带 `turn` |
| 数字 | **有绑定**：来自分析结果或测量登记 | 原子 `[@m:id]`（已有，含 `cohort_stat`；本方案扩展研究结果来源） |
| 数字 | **字面**：直接写在文字里的数字 | 跟随所在文字的等级 |
| 引用 | **有登记**：`insert_citation` 登记的文献 | 原子 `[@c:id]`（已有） |
| Word 结构 | **原样**：EndNote 域、脚注、公式 | 原子 `[@w:id]`（已有） |

### 2.2 两条规则

**规则一：AI 的写入不能降低内容的来源等级。**

- AI 不能删除或改写「人」等级的文字。要改，只能走建议模式（人采纳 = 人确认，采纳后的文字升为「人」）。唯一例外是 2.3 的「安全小改」。
- AI 不能把有绑定的数字换成字面数字，不能删掉已登记的引用和 Word 结构（已有守卫，纳入本规则）。
- AI 写入的文字一律是「AI 未确认」，直到人确认。

**规则二：AI 只能断言它观察到的东西。**

- **人工修改**：AI 不能覆盖它没读过的人工修改（已有，`noteSeen`）。
- **数字**：AI 新写入的字面数字必须有来源，并且以正确的方式表明来源。按数字出自哪里分三种情况：

  | 数字出自 | 要求 |
  |---|---|
  | 稿件本身（如方法里写过的 n = 120） | 可以直接写 |
  | 本研究的分析结果（工具返回） | 可以写；严格模式下必须用绑定原子 |
  | 参考文献 | **同一句话必须引用这篇文献**，而且数字必须出现在这篇文献已保存的摘要或全文里 |
  | 以上都没有 | 拒绝（大概率是编的） |

  文献数字的核对直接拿 `citation_abstracts` / `citation_fulltexts` 里保存的原文做，不依赖本轮读过什么：AI 上一轮读过、这一轮才写，同样能判断。这条规则拦住两类错误：把文献里的数字写成本研究的结果（出处错误）；文献是真的、数字却对不上（张冠李戴或抄错）。只有摘要、数字可能在全文表格里时，提示「无法核实」交给用户确认，不直接拒绝。
- **引用**：AI 新插入的 `[@c:id]`，这篇文献的摘要或全文必须已经保存在系统里（`citation_abstracts` / `citation_fulltexts`），只登记了题录不够。现有的 `guardCitationSupport` 关键词匹配保留，作为第二道检查。
- **文字照抄**：读过的文献原文，连续很长一段（暂定 ≥ 12 个英文词或 ≥ 30 个汉字）原样出现在 AI 写入的文字里，转为建议模式并提示改写或改用直接引语。只提醒、不硬拦：方法学里的标准表述有时确实和文献接近。

### 2.3 安全小改（受控的降级）

问卷里多数医生希望「小改直接改，大改先给建议」。在信息流控制里，这对应一个**受控降级**：在严格的条件下，允许 AI 直接改「人」等级的文字，被改动的字降为「AI 未确认」并在界面上标出。

同时满足下面五条才算安全小改，否则自动转为建议模式（不是报错，AI 不用重试）：

1. 只用 `replace_text` 做片段替换，单处改动不超过 40 个字符，单轮累计不超过 5 处。
2. 不碰数字、百分号、比较符号（`<` `>` `≤` `≥` `=`）。
3. 不碰引用原子、测量原子、Word 结构原子。
4. 不碰否定词和措辞强度词（中英文表，如「不 / 未 / 无 / 可能 / 显著 / 证实 / not / no / may / might / significant / suggest / demonstrate / prove」）。
5. 不在合作者的待采纳修订里，不碰开放评论的锚点（沿用已有守卫）。

这一条就是之前讨论的「按改动大小区分直接改和建议」，现在有了原理依据：**能直接改的，是不会改变事实和主张强度的改动。**

用户可以在文档设置里关掉安全小改（一律走建议）。

## 3. 形式化保证（论文用）

把文档看成带标签的符号序列，AI 的一次写入 `w` 把文档 `D` 变成 `D'`。守卫对 `(D, D', 观察记录 O)` 做确定性检查，保证：

- **P1（人的内容不被暗改）**：`D` 中所有「人」等级的符号，在 `D'` 中要么原样保留，要么只经安全小改改动并被重新标为「AI 未确认」。
- **P2（绑定不降级）**：`D` 中所有 `[@m]`、`[@c]`、`[@w]` 原子在 `D'` 中仍然存在（用户明确删除整块的情况除外）。
- **P3（来源可追溯）**：`D'` 相对 `D` 新增的每个字面数字 `x`，要么出现在 `D` 或本轮工具结果 `O` 中；要么所在句子引用了文献 `c`，且 `x` 出现在 `c` 已保存的原文 `S(c)` 中。新增的每个 `[@c:id]`，`S(c)` 非空。
- **P4（读取范围）**：`w` 触及的每个块，若在 AI 最后一次读取之后被人改过，`w` 被拒绝。

P1–P4 都由写入前的确定性检查实现，可以对检查函数逐条证明「拒绝所有违反的写入」。论文里同时报告检查的误拦率（拒绝了不违反的写入），这部分靠实验测量。

**保证不了的**：数字和引用都对、但意思被改了（比如把「相关」写成「导致」却没用到 2.3 的词表）。这属于语义判断，交给第 8 节的措辞强度提醒和论文二的深度评审，论文里明确写成局限。

## 4. 实现

### 4.1 文字的来源标记

在 `model/schema.ts` 加一个 mark：

```ts
prov: {
  attrs: { by: {}, turn: { default: null } },  // by: 'ai'；人写的文字不加标记
  inclusive: false,                             // 在 AI 文字后面打字，不继承 AI 标记
  excludes: '',                                 // 可与其他 mark 共存
}
```

只给 AI 文字加标记，人写的文字不加。原因：

- 绝大多数文字是人写的，不加标记最省空间。
- 旧文档、导入的 Word 稿自然就是「人」等级，不需要迁移。
- 标记随文字在 Yjs 里同步，复制、拆段、合段时自动跟着走。

**由服务端打标记，不信任客户端**：

- AI 写入（`OpService.edit`，`actor: 'ai'`）：提交前，对每个被改动的块做文字级对比，新插入的字加上 `prov{by:'ai', turn}`。
- 人的修改（`Documents.record`，`actor: 'user'`）：同样对比，新插入的字去掉 `prov` 标记。这样人在 AI 文字中间改了几个字，改的部分自动成为「人」等级。
- 采纳建议：采纳后的块整体去掉 `prov`（人采纳 = 确认）。
- 确认：新增操作 `confirm_text`（块 id，可选范围），去掉范围内的 `prov`。**只能由用户本人执行**，登记到 `parity.test.ts` 的 `NOT_FOR_AI`：AI 不能确认自己写的东西。

### 4.2 给 AI 看的视图

带注释的 Markdown 里用最少的字标出 AI 未确认的文字，比如 `⟦…⟧`，并在视图开头说明：「⟦⟧ 内是你写的、用户还没确认的文字，可以直接改；其余文字只能用建议模式或安全小改。」这样 AI 能自己判断该用哪种方式，少撞守卫。

### 4.3 观察记录

- 新表 `turn_observations(turn_id, kind, ref, numbers, at)`：`kind` 为 `doc_read`、`tool_result`、`citation_read`；`numbers` 是从返回内容里抽出的数字集合（规整后：去千分位、统一小数点和负号、百分数同时记 `12.5` 和 `12.5%`）。
- 记录点：`doc_read` / `doc_outline` 返回时；研究、数据集、统计类工具返回时；读文献摘要、全文的工具返回时。
- `noteSeen` 目前存在内存里，服务重启就丢（`ops/service.ts` 第 357 行）。一并改为存进这张表，P4 才能在重启后仍然成立。

### 4.4 守卫的重组

新增 `ops/provenance.ts`，集中实现 P1–P3 的检查，`OpService` 在现有守卫之前调用。现有守卫的错误码不变（`conflict_user_edited`、`existing_citation`、`measurement_lost` 等），AI 侧的提示和已有测试都不受影响；新增三个错误码：

| 错误码 | 含义 | 返回给 AI 的提示 |
|---|---|---|
| `human_text_protected` | 想直接改「人」等级的文字，且不符合安全小改 | 已自动转为建议提交；或说明改用 `mode: 'suggest'` |
| `unobserved_number` | 写入的数字在本轮没观察到 | 列出数字；提示先读来源、或用绑定原子 |
| `unread_citation` | 插入的引用本轮没读过摘要或全文 | 提示先读这篇文献 |

`guardUserContent` 的「从日志猜人写的片段」由 P1 取代，保留一个版本作为对照，两者结果一致后再删掉旧实现。

**实现时确定的细节（第 2 期）：**

- 开关：`new OpService(docs, …, { provenance: true })`，线上在 `index.ts` 开启；单元测试默认关闭，免得与其他功能的断言互相干扰，来源规则由 `tests/provenance-guard.test.ts` 专门在开启状态下测。全部测试在开启状态下跑过一遍：变化都是「AI 直接改人写的文字」变成待采纳修订（整段改写导入的段落、删表格行列、给人写的句子补引用、回答批注时改写被批注的文字、全文批量替换），符合规则本意。
- 观察记录：平台回合用回合 id 作键，`turns/service.ts` 从 dsh 的每个 `tool/result` 事件（含 dsh 自己的 shell / Python 输出、子代理）取数字，用户消息里的数字也记；外部智能体（没有平台回合）用 `sess:<会话>` 作键，只能记经本 MCP 返回的结果。没有键的写入（服务端内部按模板生成）不做数字出处检查。观察记录保留 14 天。
- 数字出处按句子判断：改动区域里新写入的文字按句子分段，每段只带本句的引用；句末标点后紧跟的引用也算本句。
- 合并段落等跨块搬运：新出现的文字若原样来自被去掉的块，沿用那块的来源，不算改动人写的文字，被搬走文字的块也不算删除（来源混杂时按 AI 记）。
- 给 AI 的使用说明（`mcp/server.ts` 的 instructions）写明三条规则与返回码的处理方式；`doc_edit` 转为待采纳修订时在 note 里说明原因，交给用户核对的数字放在 `needs_user_check`。

### 4.5 研究结果绑定

沿用测量原子：在 `measurements/service.ts` 的来源表里新增 `study_result` 来源，指向研究模块一次已保存的分析（回归、生存分析、Table 1 等），字段为该分析输出的 HR、OR、95% CI 上下限、P 值、样本量等。重新分析后，稿件里的数字随之更新，这正是 `cohort_stat` 已经在做的事，只是来源更多。

## 5. 界面

- **AI 文字标识**：编辑器里给「AI 未确认」的文字加浅色底纹，默认开启，菜单里可以关掉。
- **确认**：选中文字或段落，点「确认」；段落菜单里有「确认本段」。
- **保护记录**：每轮 AI 结束后在对话里显示一行，例如「保护了 2 处：保留了您改的 HR 1.12；拒绝了 1 个未查到来源的数字 0.032」。不弹窗，不打断。

**实现（第 3 期）：**

- 文档上方提示栏（`provBanner`）：「有 N 段含 AI 写的、还没确认的文字」+「下一处」「隐藏底纹」「全部确认」；工具栏「确认」确认光标所在或选中的段落（`web/src/provenance-ui.ts`）。
- 确认接口 `POST /api/docs/:id/confirm-ai {node_ids?}`，不给 AI（`parity.test.ts` 的 NOT_FOR_AI）。确认只去掉标记、不改文字，以 `system` 落库：否则会被当成「用户改过这一块」，冲突守卫拦下 AI 的后续修改、记忆信号也会误记；谁确认的记在审计（`doc.confirm_ai`）。
- 个人偏好 `GET / PUT /api/me/provenance {safe_edits, shade}`，个人设置里两个开关；只能用户本人改。
- 保护记录：OpService 把转为待采纳修订、交给用户核对的数字、以及保护类拒绝（`unobserved_number`、`unread_citation`、`conflict_user_edited`、引用与测量守卫）按回合记进 `provenance_events`（试探不记）；回合结束时 `turns/service.ts` 汇总成几行平常的话（`protectionSummary`），以 `protection` 事件发给对话，显示为「写作保护」小卡片。

**实现（第 4 期）：**

- 分析结果登记（`research/results.ts`，表 `analysis_results`）：MCP `result_register` / `result_list`，HTTP `GET / POST /api/analysis-results`。一个效应一个结果，统计量为 `RESULT_FIELDS`（estimate、ci_low、ci_high、p_value、n、events、pct、mean、sd、median、q1、q3）。**AI 登记的数值必须在本轮观察记录里**（与规则二同一套），登记表不能成为绕过数字出处检查的后门；用户本人登记不受此限。同一用户同名再登记 = 重新分析，数值变了版本 +1，稿件里绑定的数字随之更新。
- 测量来源新增 `analysis_result`：读者是登记者或结果所在研究的成员才看到当前值，其余只看快照；不需要患者模块。P 值单位 `pval`，小于显示精度写「<0.001」。
- 来源证明 `GET /api/docs/:id/provenance`（导出菜单「来源证明 .json」）；AI 使用声明 `GET /api/docs/:id/ai-disclosure?lang=zh|en`（导出菜单「AI 使用声明」，中英两版可复制，有未确认的 AI 文字或无原文的引用时先提醒）。声明只陈述平台记录到的事实：有未确认的段落时只写「尚未逐段确认」，不替作者声称已审阅。AI 通过 `doc_manage` 的 `provenance` / `ai_disclosure` 同样能取。

## 6. 兼容性

### 6.1 已有文档

已有文档里的文字都没有 `prov` 标记，一律视为「人」等级。这会把以前 AI 写的文字也当成人写的，结果是更严格（AI 改它们要走建议），不会更危险。可以选做一次回填：`node_changes` 里只有 `actor='ai'` 改过、从没被人改过的块，整块标为 AI 未确认。

### 6.2 导出

- Word 导出不带 `prov` 标记，导出的稿件和现在完全一样。
- 新增「来源证明」：一个附带的 JSON 文件，列出每个绑定数字对应的分析、每条引用、每段 AI 文字及其确认状态。
- 新增「AI 使用声明」草稿：按来源证明统计，比如「AI 修改了讨论部分 23 处，其中 21 处已由作者确认；没有引入数字或参考文献；所有统计数字均来自分析 #3」。中英文各一版，供作者粘进投稿系统。

## 7. 分期实施

| 期 | 内容 | 主要改动 | 对论文 |
|---|---|---|---|
| 1 | 来源标记与观察记录 | `prov` mark；服务端打标记；`turn_observations`；`noteSeen` 持久化 | 地基 |
| 2 | 两条规则的守卫 | `ops/provenance.ts`：P1 + 安全小改自动转建议，P3 数字与引用观察前提 | 核心实验对象 |
| 3 | 界面 | AI 文字底纹、确认操作、保护记录 | 用户研究、误拦体验 |
| 4 | 研究结果绑定与可验证导出 | `study_result` 来源；来源证明；AI 使用声明 | 数字规则的最强形态；可验证稿件 |
| 5 | Word 回流合并 | 单独出设计方案 | 人工修改规则的真实场景 |

每期都要满足：`pnpm test` 全过；`parity.test.ts` 登记新接口（`confirm_text` 不给 AI）；第 2 期起在论文的基准稿件上测误拦率，误拦率过高时先调规则再进入下一期。

## 8. 不在本方案里的

- **措辞强度提醒**：AI 改写后对比前后措辞强度，加强了就提醒。它是提醒不是规则，放在第 3 期之后单独做。
- **Word 插件**：长期方向。
- **段落内实时协同的字级合并**：Yjs 已经处理，本方案只在其上加标记。

## 9. 已确认的决定（2026-11-13）

1. **安全小改默认开启**，文档设置里可关。
2. **来源不明的数字直接拒绝**（文献数字只有摘要、无法核实时除外，见 2.2）。
3. **已有文档回填 AI 标记**：`node_changes` 里只被 AI 改过、从没被人改过的块，整块标为 AI 未确认。
4. **AI 文字底纹默认开启**，菜单里可关。
