# 导入质量评测（PDF / Word）

> 状态：2026-11-08 建立。脚本 `apps/platform/scripts/eval-import.ts`，基线 `apps/platform/eval/import/baseline.json`。

## 为什么要有

深度审稿读的是导入后的文档。导入丢了数字、表格错了位、把修订删掉的旧数字混进正文，审稿就会对着错误的内容报误报，用户却以为是自己稿子的问题。只看「能不能导入」发现不了这些问题，所以用标准答案逐项比对。

## 方法

- **标准答案**：PubMed Central 开放获取数据集（`pmc-oa-opendata`）里同一版本的 PDF 与 JATS XML。必须同版本，否则论文更正过的地方会被误算成导入错误。论文清单复用深度审稿评测的清单（`eval/deep-review/manifest.json`，19 篇，覆盖 RCT、队列、病例对照、诊断准确性、横断面、系统评价、基础研究）。
- **比对**：`eval-jats-check.ts` 的保真度检查。它不复用任何转换代码，独立从 JATS 取「应该出现的内容」，与导入后的文档比：
  - 数字按出现次数计，统计缺失与多出；
  - 文字词元缺失率；
  - 表格按合并单元格展开后，逐格比对行列与内容；行列对上的表另比合并单元格：原文被合并区覆盖的格子，转换结果是否同样被覆盖（召回），以及转换结果多出的覆盖格；
  - 章节标题（含编号）；
  - 图注计入正文；修订里「待删除」的块不算正文；
  - 结构（2026-11-08 加，针对实际查看导入结果时发现的问题）：
    - 文档第一个标题是否就是论文标题；
    - 原文每张图的图注是否落在某个图块上，以及没有图注的图块数（期刊 logo 等版面杂物、拆开的子图）；
    - 原文没有的多余标题（侧栏标签、图里的文字；作者贡献、基金等文末声明不算）；
    - 对上的标题里层级不对的个数（以「文档层级 − 原文嵌套深度」的众数为准）；
    - 原文较长段落（≥25 词）首尾是否落在同一块里（换页、换栏截断，或混进别的内容）。
- **Word 另查**：修订删除的内容是否混进采纳后的正文、域指令（`ADDIN`、`SEQ` 等）是否混进正文。

## 四条导入路径

| 路径 | 说明 |
|---|---|
| `pdf-docling` | 产品 PDF 主路径（doc-parser / Docling）。退回 poppler 的论文记为失败，不混入成绩 |
| `pdf-poppler` | PDF 兜底路径 |
| `docx-clean` | LibreOffice 由平台 HTML 生成的干净 docx |
| `docx-realistic` | 在干净 docx 上叠加作者稿件常见结构（`eval-docx-constructs.ts`）：EndNote 引文域与文献表域、SEQ 题注域、修订（插入 / 删除）、文本框、行号、多级列表自动编号 |

## 用法

```bash
cd apps/platform
pnpm eval:import --fetch                          # 下载同版本 PDF + JATS 到 data/eval/import/（不进 git）
pnpm eval:import                                  # 四条路径全跑，与基线对比；变差超过容差则退出码 1
pnpm eval:import --path docx-clean,docx-realistic # 只跑部分路径（不需要 doc-parser）
pnpm eval:import --only PMC12644478               # 只跑部分论文（不与基线对比）
pnpm eval:import --write-baseline                 # 确认是改进后，把本次结果写成新基线并提交
```

依赖：`pdf-docling` 需要 doc-parser 服务就绪（`DOC_PARSER_URL`，默认 `127.0.0.1:8005`，本地启动见 `apps/doc-parser/README.md`）；`docx-*` 需要 LibreOffice（`soffice`）。

**防退步的容差**：
- 计数类（缺失数字、多出数字、缺失标题）允许多 2%（至少 1 个）；
- 比例类（行列对上的表格数、单元格精确率、单元格召回率、合并单元格召回率）允许降 1 个百分点；
- 多出的合并覆盖格按计数类处理；
- 结构：没有图注的图块、多余标题、层级不对的标题、被截断的段落按计数类处理，图注落位的图数不允许少于基线 2%，标题认对的篇数不允许减少；
- 文字缺失率允许升 0.2 个百分点；
- 失败篇数、修订泄漏、域指令泄漏不允许增加。

改导入代码（`convert/docx-import.ts`、`convert/pdf-import.ts`、`convert/doc-parser.ts`、`apps/doc-parser`）后都应跑一遍。

## 已知局限

- 标准答案是期刊排版后的发表版（多为双栏、表格密集），作者从 Word 导出的单栏稿件 PDF 通常更容易识别，PDF 结果偏悲观。
- `docx-*` 由 LibreOffice 生成，不等于作者在 Word 里排版的稿件；真实稿件的结构（手绘表格、嵌入 Excel 对象、复杂公式）需要用真实样本补测。
- 文字部分按词元统计，不检查顺序与段落拆合；公式不比对。

## 由这套评测发现并已修复的问题（2026-11-08）

- **Word**：
  - 修订删除的旧数字被审稿读到；
  - 域代码（EndNote 引文编号、SEQ 题注编号）不对外提供文字，审稿与检索都读不到；
  - 自动编号的章节号丢失；
  - 文本框文字被截断，且混入域指令。
- **PDF（Docling）**：
  - 跨页续表被拆成多张；
  - 森林图被当成表格；
  - 合并单元格丢失：doc-parser 只输出起始格文字，合并范围丢掉（19 篇里 Docling 识别出 273 处合并，全部丢失）。现在输出 `spans`，平台按此生成跨行 / 跨列单元格，合并格召回 0 → 70.2%；
  - 图注审稿读不到（Word 同样）。
- **审稿读表格**：`extractTableSummaries` 原来按单元格节点逐个读，不看合并，有合并单元格的表（Word 一直有，PDF 现在也有）列会错位，表头样本量对不上列。改为按逻辑网格读：表头的跨列合并铺到覆盖的每一列，正文合并单元格只在起始格保留文字。
- **审稿用不可信的表**：PDF 表格识别坏了（横排表方向反了、几行挤进一格、表注混进单元格）时，规则核查照样按格算数，会产生误报。现在 Docling 导入的稿件审稿前逐表判断（`claims/table-trust.ts`），不可信的表不参与核查、不交给模型，并告诉用户跳过了哪几张；poppler 兜底导入的稿件仍整体跳过表格，Word 稿不判断。
  - 判断规则只看表格本身：首行大半是数字、一格挤着几个数字、数值格粘着行标签文字、表注混进单元格、只有一行或一列。
  - 校准：以「转换后的行有 85% 以上与原文某行一致」为可信标准，19 篇的 76 张 Docling 表里有 13 张不可信，规则挑出 9 张，没有误判可信的表；JATS 转出的 62 张干净表格全部判为可信。
  - 漏掉的 4 张：2 张纯文字的研究特征表，2 张只是行标签列错位、数值列正确，不影响数值核查。
- **评测语料转换**（`eval-jats.ts`）：相邻引用粘连成假数字、PMID / DOI 粘连等 8 处。
