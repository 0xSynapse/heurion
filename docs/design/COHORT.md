# 研究入组与研究数据集（第三期）

从患者库按条件筛选患者，入组到临床研究，生成只含研究编号的研究数据集。代码：`apps/platform/src/research/cohort.ts`（编排）、`src/tenancy/patients.ts`（入组、筛选、快照）。

## 1. 数据放在哪里

- **研究**在平台库（`studies`，归个人）。**入组关系与研究编号**在机构的患者库（`data/tenants/<机构>/patients.db` 的 `enrollments` 表），不进 `study_items`：
  - 患者 ↔ 研究的对应本身是患者信息，和患者数据同库，删除机构、删除患者时一起清掉（外键级联）；
  - `study_items` 的「一项只属于一个研究」（UNIQUE(kind, ref_id)）适合文档、数据集，不适合患者：同一患者可以入多个研究。
- `enrollments(study_id, patient_id, subject_id, status active|withdrawn, criteria, enrolled_by, enrolled_at, withdrawn_at)`；主键 (study_id, patient_id)，研究内 subject_id 唯一。
- **研究编号** S001、S002…：研究内递增（`seq` 表 `subject:<研究>`），不复用；移出后再入组恢复原编号；患者被删除后编号作废。
- 删除研究：清掉入组关系、待确认的入组提议与编号序列（`StudyService.onRemove`）。

## 2. 权限

- 只能用自己的研究（别人的研究当不存在，404）。
- 只能筛选、入组**自己在诊疗组里**的患者（负责人 / 成员）。机构设为「全员可见」的只读访问、机构管理员的紧急访问都不能用来入组。研究与患者自然同机构（患者库按操作者所在机构打开）。
- 机构没开患者模块时整个入组不可用。
- 入组名单里，操作者已经看不到的患者不显示代号（只有研究编号）；生成数据集时不包含操作者已不在诊疗组里的受试者（在 `skipped` 里列出）。
- 访问日志：筛选（命中的患者各一条 `cohort_screen`）、入组 `enroll`、移出 `unenroll`、生成数据集 `cohort_export`，via 区分人 / AI，detail 写明研究。未命中的患者不记（结果没有离开平台）。

## 3. 筛选条件

性别、年龄范围（按出生年份）、诊断标签包含任一（部分匹配、不分大小写）、化验条件（项目 + 最近一次 / 任一次 + 比较符 + 阈值，用换算到标准单位后的**已确认**值，见 units.ts）、化验日期窗口（化验条件只看窗口内的值；只给窗口时要求窗口内至少一次化验）。只看在管（active）患者。预览返回代号、性别、年龄、标签、匹配依据（如「肌酐 185.7 µmol/L（2025-06-10，最近一次）」）和是否已入组。

## 4. 研究数据集

- 由入组受试者快照生成，走现有数据集流程（解析、概况），自动归入研究。来源记录在 `datasets.origin`（研究、形状、项目、窗口、生成时间、指纹、受试者数）。平台生成的列在 `trusted_columns` 里，不按「疑似身份信息」拦。
- 数据集里**只有研究编号**，没有代号、备注姓名。
- 宽表：每人一行——研究编号、性别、入组时年龄、诊断标签、入组日期；每个化验项目一组列：基线（窗口内第一次）值与日期、最近值与日期、次数。数值为标准单位，列名带单位（`creatinine_baseline_umol_L`），中文标签写进数据集 labels。同一项目有无法换算的单位时，宽表只取最常见单位的值，其余只进长表。
- 长表：每次化验一行（研究编号、项目、标准单位值、单位、文字结果、异常标记、日期时间、是否换算、单位是否未识别）。
- **过期**：指纹由入组名单、受试者性别 / 出生年份 / 标签、所选项目与窗口内的已确认化验（id、值、单位、日期）算出。之后有变化（新确认、被更正替换、入组 / 移出）时最新一版标「已过期」，研究页提示刷新。
- **版本**：刷新生成新版本（v2、v3…），**旧版本保留**——已有分析（图）的来源记录指向生成它时的数据集，覆盖会让分析和数据对不上。数据与上一版完全相同时沿用那一版（只更新指纹）。
- 解析失败时报错并删掉失败的数据集。
- 机构不允许把患者数据交给外部模型（`external_model_for_patients=false`）时，AI 不能 `dataset_describe` / `dataset_open` 由患者生成的数据集；人在界面上照常使用。

## 5. 人机同等

| 界面 | MCP |
|---|---|
| 筛选预览 `POST /api/studies/:sid/cohort/preview` | `study_cohort_preview` |
| 入组 `POST /api/studies/:sid/cohort` | `study_enroll` |
| 移出 `DELETE /api/studies/:sid/cohort/:ptid` | `study_unenroll` |
| 名单、提议、数据集 `GET /api/studies/:sid/cohort` | `study_cohort_list` |
| 生成 / 刷新数据集 `POST /api/studies/:sid/cohort/dataset` | `study_cohort_dataset` |

AI 的入组 / 移出受机构设置 `ai_patient_writes` 约束：`review`（默认）时每位患者一条「入组」/「移出」提议，`direct` 时直接生效。理由：入组决定了哪些患者的数据进入可分析、可写进论文的数据集，是对患者数据的写入。提议只能由**研究负责人**确认（诊疗组的其他成员看得到，但研究归个人，不能替别人的研究做决定）；在研究页或患者页「待确认」里处理。生成数据集不需要确认：只用已经确认入组的受试者，且只读。

越权测试（tests/isolation.test.ts）覆盖新接口与 `patient_ids` 参数；人机对等测试（tests/parity.test.ts）登记了上表。
